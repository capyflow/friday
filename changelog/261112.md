## fix(模型): 模型服务的「测试」看不到结果、「保存并生效」仍在用旧模型

- 时间: `2026-11-12`

### 变更内容

设置 → 模型服务里配模型时有两处毛病：

1. 点「测试」**没有任何反馈**——测试结果渲染在折叠区里，而测试按钮在折叠头，
   行收起时点了等于没点（用户连点 9 次也看不到结果，只能以为「测试完不成」）。
2. 新加一个模型后点「保存并生效」，**生效的仍是旧模型**——新增的条目没有被
   选中，「保存并生效」把旧模型继续留在生效位上，看着像保存了，实际没换。

另外，连接测试失败时一律说「服务响应不兼容，请检查 API 地址、模型名与协议」，
把服务商自己说的真话藏了起来（比如阶跃星辰的
`you have no active step plan subscription`——账户套餐没生效，与地址、协议无关）。

### 修改原因

第 1 条是纯前端的位置问题：测试结果写在 `.pm-body` 里，而 `.pm-body` 是
`v-show` 的折叠区，默认收起。按钮在折叠头、结果在折叠体，用户看不到。

第 2 条是 `addRow()` 的条件写窄了：只在「一个模型都没有」时才选中新行，
于是加第二个模型时生效位仍挂在旧条目上。

第 3 条是探针把服务商的报错正文整个丢掉了（只留一个通用文案），用户没法判断
到底是地址写错、协议不对，还是账户没额度。

### 实现方式

- `web/src/components/ProviderSettings.vue`：
  - 测试结果从 `.pm-body` 里挪到行级（折叠区之外），收起也看得见；
  - `addRow()` 里新增的条目直接设为生效项（与原注释的意图一致）。
- `internal/admin/setup.go`：
  - `providerHTTPFailure` 带上服务商自己说的原因（`providerErrorMessage` 兼容
    `{"error":{"message":...}}`、`{"error":"..."}`、`{"message":...}`、`{"detail":...}`）；
  - 400 单独归类为「请求被模型服务拒绝，请检查模型名、账号权限与额度」，
    不再笼统说「不兼容」；
  - **服务商把密钥原样回显在报错里时先脱敏**（`redactSecret`）——诊断会进前端
    提示，不能带密钥出去（既有测试一直盯着这条）。

### 涉及文件

- `web/tests/provider-settings.test.js`

- `internal/admin/provider_test.go`

## feat(提示词): 小五按 app 设置的语言回复，内置与 ACP agent 共用一条规则

- 时间: `2026-11-12`

### 变更内容

小五回复的语言现在跟着 app 设置走，默认中文。设置页新增「回复语言」一节
（设置 → 模型与人格 → 回复语言），预设中文 / English / 日本語 / 한국어 /
Deutsch / Français / Español，也可以自定义语言名；保存后热生效并写回
config.yaml。

### 修改原因

以前没有这条约束：模型默认用英文答，用户问中文得到英文回复；工作区里的外部
agent（codex/zcode 等）更是各说各话——它们连 Friday 的系统提示词都看不到，
语言完全由各自的默认决定。

规则要覆盖两处，缺一不可：

- **内置 agent**（聊天页，以及工作区里那个内置的「friday」条目）：规则写进
  系统提示词。
- **ACP 外部 agent**：没有 Friday 的系统提示词，规则随 prompt 块发过去。

两处共用同一段文字、同一个值（`internal/agent.LanguageRule` +
`config.EffectiveLanguage`），否则会出现「内置说中文、外部说英文」。

### 实现方式

- `config.Config` 新增顶层 `language` 字段（空 = 中文），`EffectiveLanguage()`
  统一取值；`UpdateLanguage` 写回 config.yaml（yaml.Node 编辑，保留注释）。
- `agent.LanguageRule(lang)` 生成「回复语言」规则段：内置 agent 把它拼进系统
  提示词（人设之后、工具规则之前）；自定义 `systemPrompt` 也照样追加——否则
  设置里的语言在自定义提示词下会静默失效。
- ACP 外部 agent：`internal/acp/manager.go` 在 prompt 块最前面插入规则块；
  内置 agent 走同一个 Brain，**不重复注入**（否则用户那句话前面会多出一段
  本该是规则的东西）。
- 热生效：`agent.ReloadLanguage` 重建 Agent（系统提示词随之重写，对话上下文
  不丢），并写回 config.yaml；接口 `GET/POST /api/language`。
  `config.Apply` 的发布白名单里补上 `Language`——不发的话只有文件变了、
  内存里还是旧值。
- `Config.Apply` 之外，ACP 侧通过 `SetLanguage(fn)` 注入取值函数（而不是值），
  语言改了不必重启内核。

## fix(界面): 会话页对话拿不到响应，刷新一下才好的问题

- 时间: `2026-11-12`

### 变更内容

会话页（工作区里的对话、生活模式的聊天）发一句话后，回复迟迟不出现，非得刷新一下页面
才看得到——因为答案其实早就到了服务端，只是没流回页面。

### 修改原因

改造后的前端用一条 `/api/events/stream` 长连接收一轮对话的事件（见 261111 的
「会话事件总线」）。但**订阅客户端没有管住自己的连接**：

- `events.js` 重连时只把新连接存进 `es`，**不关掉被换下来的那一条**。EventSource
  不会因为「被换下」就自己断开，旧连接于是变成僵尸——服务端照样往它写帧、浏览器照样
  收帧（但被 `es !== sock` 丢掉），连接却一直占着。
- 僵尸连接报错时还会再触发一次重连，等于每次出错都再多泄漏一条，滚雪球一样攒。
- `stop()` 只关当前那一条，之前泄漏的全留着；`visibilitychange` 监听器也从不摘除。
- 窗口切来切去（`visibilitychange`）每触发一次就重开一条连接，哪怕旧的那条好好的。

浏览器的同源 HTTP 连接池只有 6 条。几个僵尸占满之后，新连接根本建不起来（一直挂在
排队里），页面就再也收不到任何事件——刷新一下把所有连接清掉，才恢复。这正是
「必须刷新页面才看得到回复」的原因。

日志里的证据：同一个会话 `acp:8337b7d7135198bd` 上同时挂着 **4 条**事件流连接
（其中 3 条 `since=2`），而应用侧的常规请求在那一刻全部停摆。

服务端也有两处配合不力：

- 客户端断开后，handler 还阻塞在等事件上，`defer sub.Close()` 迟迟不执行——
  **每刷新一次页面，内核里就多留一条没人读的订阅**。
- 连接没有任何回收机制，僵尸订阅可以活到进程结束。

### 实现方式

前端 `web/src/events.js`：

- 用 `sockets` 集合记下这次订阅建过的**所有**连接；`connect()` 重连前先关掉上一条，
  `stop()` 把这一组全关掉——不再有僵尸连接。
- 僵尸连接（`es !== sock`）出错不再触发重连，只有关着的当前连接才重连。
- `visibilitychange` 只在「连接真的不在了」（`readyState !== OPEN`）时才补连，
  连接还活着就不重开；`stop()` 时把监听器一并摘掉。

服务端 `internal/admin/acp.go` 的事件流端点：

- 监听 `Request.Context().Done()`：客户端一断开就立刻退订，不再攒着没人读的订阅。
- 加 15 分钟空闲上限：这么久一个事件都没有就主动断开，回收客户端已经忘了的僵尸订阅。
  断开后客户端带 `since` 重连（退避 1s 起），内容从环形缓冲补齐——空闲窗口里本来
  就没有新事件，不会丢内容。

### 涉及文件

- `web/src/events.js`
- `web/tests/events.test.js`
- `web/tests/setup-env.js`
- `internal/admin/acp.go`
- `internal/admin/events_test.go`

## fix(智能体): 连接中断的轮次自动重试（额度类错误除外）

- 时间: `2026-11-12`

### 变更内容

外部 agent 的连接半路断掉（对端把管道掐了、进程崩了）时，这一轮以前直接判失败：
用户看到「agent 连接中断: {"code":-32603,"message":"Internal error","data":{"error":"peer disconnected before response"}}」，
这一轮的话等于白说了。现在这类**链路故障**会自动重试：重建 agent 进程与会话，把同一条消息
原样再发一次，最多重试 3 次（首次失败后再试 3 次，共最多 4 次尝试）。

重试期间会话里会出一条状态提示「<agent> 连接中断，正在重试（第 N/3 次）…」，桌面端与手机端
都能看见；重试成功这一轮照常出答案，失败则如实报错并带上「（已重试 N 次仍失败）」。

**额度/配额用完不重试**：quota、余额不足、计费错误这类错误重试多少次都是同一个结果，
只是白烧额度，原样交回给用户处理。

### 修改原因

这类错误是"路断了"而不是"被拒绝了"：agent 进程崩掉时它一个指令都没执行完，
用户要的只是"把这句话发出去"。重连后重发通常一次就成了——不是可选项，是本来就该做的事。
额度用完恰恰相反：重试只是把同一个失败重复三次，还把额度进一步烧光。

### 实现方式

新增 `internal/acp/retry.go` 承担"这一轮失败后要不要重来"的判据与执行：

- `errorText` 把 ACP 形状的错误（`{"code":-32603,"message":"Internal error","data":{"error":"..."}}`）
  摊平成一段文本再匹配，否则真正的原因藏在 `data.error` 里，字段名还会干扰判断；
- `transportFailure` 认链路层故障（peer disconnected / connection reset / broken pipe / 进程没了等），
  `quotaExhausted` 认额度类错误，两者相斥——额度优先，额度命中就不重试；
- `retryPrompt` 执行重试：每次都走 busy 自愈同一条重建路径（`killLive` → `ensureLive` →
  `session/load` 重接），所以 agent 支持重接时上下文还在，不支持时照例标注"上下文已重置"；
  退避 0.5s / 1s / 2s。

不重试的几种情况：用户按了停止、内核关闭（`tctx` 已取消）、这一轮已经吐过正文（重发会把回答
重复一遍）、会话忙（归既有的 busy 自愈管）。

`internal/acp/manager.go` 的 `sendTurn` 在 busy 自愈之后接上重试，并把重试次数带进错误文案；
`turnHooks` 提成局部变量，重试提示因此能走事件总线（两端都看得见）。
`onProcExit` 加了一道守卫：只有登记在册的连接真的死了才清理——旧进程的退出回调可能比重试
拉起的新进程注册得慢（agent+目录是同一个 key），无差别清理会把刚建好的新连接一起带走，
它的会话从此收不到任何事件。

验证：`internal/acp/retry_test.go` 新增 4 条守护用例（断线后重试并接上这一轮、额度用完不重试、
一直断线重试到上限后如实报错、判据表逐条核对）；`go test ./internal/...` 全绿。

## feat(模型): 模型服务支持 OpenAI / Anthropic / Gemini 三种协议

- 时间: `2026-11-12`

### 变更内容

「设置 → 模型服务」的每条模型档案新增**协议**下拉：

- **OpenAI 兼容**（默认）：`{baseURL}/chat/completions`，DeepSeek / StepFun / 智谱 / MiniMax 的 `/v1` 都走这条；
- **Anthropic 兼容**：`{baseURL}/v1/messages`，Claude 官方与 MiniMax 推荐的 `/anthropic` 端点走这条；
- **Gemini**：`{baseURL}/v1beta/models/{model}:generateContent`。

连接测试按所选协议发真实请求，文本与图片诊断都分别适配三种协议的报文形状；
旧配置与旧模型库条目无需迁移——协议留空一律按 OpenAI 兼容处理。

### 修改原因

此前模型层把协议写死成 OpenAI 兼容：配置校验只放行 `provider.name: openai`，
测试接口固定拼 `/chat/completions`，前端也没有协议字段。订阅 MiniMax M Plan 的用户
按官方推荐填 `https://api.minimaxi.com/anthropic` 后，Friday 会把它拼成
`…/anthropic/chat/completions`，直接 404，表现为「测试连接报错」。
底层 vortexagent 早已实现三种协议，缺的只是 Friday 配置层与管理接口的暴露。

### 实现方式

- `internal/config/config.go` 新增 `ProtocolOpenAI/Anthropic/Gemini` 常量与
  `NormalizeProtocol`（空 = openai）；`ModelProfile` 增加 `protocol`；
  `Validate` 与 `UpdateProviderModels` 按协议校验并写回扁平 `provider.name`。
- `internal/agent/reload.go` 校验并投影协议，协议变化触发 provider 重建；
  `robot.go` 按协议构造 provider。Anthropic 协议经自定义 RoundTripper 给
  **非 api.anthropic.com** 的主机补 `Authorization: Bearer`——官方只认
  `x-api-key`，而 MiniMax / 智谱等兼容网关按 Bearer 鉴权；不改 vendor，升级依赖不丢。
- `internal/admin/setup.go` 把连接测试拆成 `probeOpenAI` / `probeAnthropic` /
  `probeGemini`，共用 HTTP 错误映射与图片拒绝识别；`ext.go` 的模型视图回传协议。
- 前端 `ProviderSettings.vue` 用 `SelectBox` 加协议下拉、按协议提示地址示例、
  摘要行显示 Anthropic / Gemini 徽标。

## feat(界面): 连续的思考与工具调用收成一条过程行

- 时间: `2026-11-12`

### 变更内容

时间线里 agent 跑长任务时，「思考 / Bash / 思考 / 执行工具 N 次 / …」一路平铺
十几行，把回答顶出屏幕。现在中间没有正文隔开的连续思考/工具行会收成一条摘要：
「2 次思考 · 5 次工具调用」（圆点分隔），点开才列出全程——思考行、工具叠逐条
可见，行为不变。流式期间收着也看得见进展：摘要标题实时跟随正在写的思考预览
（灯泡呼吸），工具在跑前导转环，有失败告警圈加「N 次出错」，不把错误藏进展开区。

只有一行的过程维持原样（单条思考、单次工具、纯工具叠），不多套一层折叠；
正文一出现就断开过程，下一轮的思考/工具另起一条摘要。

### 实现方式

- `web/src/components/TimelineBlocks.vue`：`rows` 计算改两层归并——先按原口径把
  相邻工具并成叠，再把中间没有正文的思考/工具行并成过程行。成员行不摘除、只藏起
  （`v-show` 跟随摘要头开合），开合状态记在过程首块的 `gopen` 上，流式重渲染不丢。
- `web/src/style.css`：新增 `.proc-in`（成员行缩进 21px，与叠内条目同底）；摘要头
  挂 `tool-stack proc` 类，直接借用叠的开合箭头与失败配色。
- 测试：`chat.test.js` 时间线主用例与块结构用例改写为新交互；
  `timeline-blocks.test.js` 新增归并计数、展开全程、单行不收、正文打断、流式预览
  等用例。
