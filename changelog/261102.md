### 变更内容

抽屉新增「验证」标签：时间线里出现的 localhost 地址自动列成预览入口，可内嵌 iframe 或新窗口打开，也能手填本机地址（外站直接拒）；检查命令按目录标志文件给建议（package.json scripts 并认 pnpm/yarn、go.mod、Cargo.toml、pytest 标志、Makefile 兜底），也可手填一条，运行后显示状态、退出码、耗时与输出尾部，失败行标红。新增 GET/POST /api/acp/threads/:id/checks、GET .../checks/:run、POST .../stop 四个接口。

### 修改原因

agent 说「做完了」不等于验证过。此前 Friday 里只有文字时间线，改完前端要看效果、测试挂了要看是哪条用例，都得回终端自己开；而这些命令本来就是 Friday 在本机起进程，不跟审批与超时同源就等于开了个没护栏的口子。

### 实现方式

internal/acp/verify.go 记一次运行（awaiting→running→passed/failed/timeout/killed/denied/error），执行前用 approval.Queue.RequestCancelable 强制挂一张「验证命令」审批卡（运行看板可批），批准后 /bin/sh -c 在会话主目录起进程，独立进程组 + CommandContext，停止与超时都杀整组；输出落临时文件只回读尾部（64KB / 400 行 / 去 ANSI），列表接口不带输出、选中那条走详情接口，跑完自动刷新详情。毁灭性片段按本地黑名单先拒、不入队；同会话单飞、记录留 10 条且不落盘（重启后「在跑」无意义）。内嵌 iframe 不带 allow-same-origin，预览页读不到 Friday 的登录态。

## fix: 审批档位分层退让并把实际落点标出来（V-1/V-4）（`edca306e4624`）

### 变更内容

工作区档位到 agent 审批模式的映射从「一层关键词」改成分层退让：先找语义等价档，找不到只朝同样能干活但更保守的方向退一档（每次都问→可写受限，自动→自动但不免审批）。线程上记下发给 agent 的实际取值 policyValue / policyValueName / policyFallback，会话头部直接写「审批档位实际是 Workspace Write」，编辑工作区弹窗的说明同步讲清退让规则。

### 修改原因

261030 真机验收发现 codex 只报 read-only / workspace-write / agent / agent-full-access，「每次都问」命中不到任何关键词 → Friday 不改它的设置，进程实际跑在 Auto review（等于自动放行）。用户拍板的默认档位在 codex 上名不副实，而界面上只有一行「未下发」，看不出跑的是哪一档——这正是「不敢把盘交给它」的那个洞。

### 实现方式

approvalTiers 按档位给出候选层，pickApproval 逐层扫取值（Value+Name 一起匹配）；两条红线写进代码注释与用例：ask 绝不命中自动档，也绝不悄悄退成只读（只读是另一个档位，用户想只读会显式选）。挑不到可用档就明确不下发，提示里列出可选项并提醒「它自己的默认档可能比每次都问更宽松」。手动 chip 选择仍由 reapplyChoices 随后覆盖。

## fix: 并发排队可见、可取消，槽位按取到时的表归还（V-3）（`6c4a6fde9c92`）

- Commit: `6c4a6fde9c9210fc8a8c628f0db6512b0f51cdc2`
- 时间: `2026-11-02T17:08:13+08:00`

### 变更内容

等并发槽位期间把会话标成 queued（头部/会话列表/运行页都列出来，状态点带呼吸），时间线的 status 帧写明占用比「并发的智能体进程已跑满（2/2），排队等空闲槽位…」；Stop 在没有 ACP 会话可取消时撤掉的就是这次等待，运行页据此显示「取消排队」并二次确认；有人排队时刚跑完的空闲连接 5 秒让位，不再守满 IdleKillSeconds。

### 修改原因

真机验收看到 maxConcurrent=2 被两条空闲连接占住后，第三个会话发了消息既不进 running 也不进看板，用户只能猜它死没死；同时“opencode 失败那轮之后槽位没恢复、重启才好”说明槽位记账本身有问题——不修就是“上限 2 用着用着变 0”。

### 实现方式

acquireSlot 在 m.mu 下记下这次用的 channel 与取消句柄（m.queueCancels），拿到或被取消后统一收尾，List 里发现没有对应句柄就把 queued 回落 idle，不留僵尸状态；releaseSlot 一律非阻塞，spawn 失败与 Reload 换表都不再阻塞在 <-m.sem 上——老代码那条阻塞归还在计数被打乱时会死握着 spawnMu，之后所有会话都起不了进程；Reload 重建槽位表时按存活连接重新占位并把 ps.slot 指到新 channel，上限调小则多出来的连接直接回收；重启加载时 queued 与 running 一样转成 interrupted。
