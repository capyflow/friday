## 深色下 toast 文字看不见

- 现象：登录成功的「登录成功，欢迎回来 👋」气泡在深色下是一团近乎黑色的字压在近黑底上，只剩 emoji 能认。
- 根因：`#toast` 基础规则是 `background: var(--primary); color: var(--on-primary)`，深色覆盖只改了背景（`rgba(22,22,22,.92)` 炭灰玻璃）没改文字色。261014 深色去紫把 `--primary` 翻成亮灰反白、`--on-primary` 相应翻成 `#141414`，于是这条覆盖继承到了一个"给亮灰底用的深色文字"。同批改动的用户气泡（`html[data-theme="dark"] .mrow.user .bubble`）当时补了 `color: var(--fg)`，toast 漏了。
- 修复：深色 `#toast` 补 `color: var(--fg)`。`.err` 变体不设文字色、继承同一条，一并解决。全库核过 `--on-primary` 的其余 8 处用法，都是与 `background: var(--primary)` 成对出现的（深色下即亮灰底深字，本就是设计意图），没有第二处同类漏网。
- 验证：一次性 harness 截图核对深浅两色 × 普通/`.err` 四种组合（`/tmp/friday-icons/toast-{light,dark}.png`），浅色未受影响；`npm run build` 重建 webdist。

## fix: 深色下 toast 文字继承反相后的 --on-primary 而不可读（`8277aa983364`）

- Commit: `8277aa98336455150ecb2b31bf08391daa9b78ca`
- 时间: `2026-10-15T15:07:24+08:00`

### 变更内容

深色主题的 #toast 覆盖补 color: var(--fg)，普通与 .err 两种 toast 一并恢复可读。

### 修改原因

#toast 基础规则是 background: var(--primary) + color: var(--on-primary)，深色覆盖只把背景换成炭灰玻璃却没换文字色；261014 深色去紫把 --primary 翻成亮灰反白、--on-primary 相应翻成 #141414，于是深色 toast 成了近黑字压近黑底（登录提示只剩 emoji 可认）。同批改动的用户气泡当时补了 color: var(--fg)，toast 漏了。

### 实现方式

在 html[data-theme="dark"] #toast 规则内补 color: var(--fg)，.err 不设文字色、继承同一条。核过 --on-primary 其余 8 处用法均与 background: var(--primary) 成对出现（深色下亮灰底配深字是设计意图），无同类漏网。

### 涉及文件

- `web/src/style.css`

## feat: 聊天时间线降噪：图标语义化、轮末 token 汇总与上下文占比压缩（`2a046b111fda`）

- Commit: `2a046b111fda051486bda30eb1619c74bee58489`
- 时间: `2026-10-15T15:09:59+08:00`

### 变更内容

三件事同属聊天时间线的信息密度整改。(1) 折叠行前导改语义图标——思考=灯泡、工具调用=扳手，两行共用 14px 描边 SVG 槽 .step-ico，工具行成功不再打勾、仅失败换告警圈并整行转红 .tool.is-fail，运行中保留旋转环；(2) token 口径收口——roundDetail 去掉 token 段只留耗时，本轮总用量改由 done 帧的 turn={in,out,ms?} 一次性带回，时间线末尾 .turn-total 落一行汇总；(3) 上下文占比与手动压缩——新增 Brain.ContextSnapshot / CompactContext 与 GET /api/context、POST /api/context/compact，composer 左组加上下文 chip（三档配色）与弹层（已用/窗口、阈值刻度、压缩与清除）。

### 修改原因

每轮 LLM 都摊一行「耗时 · a+b tokens」，一轮工具多的问答刷出四五行雷同数字，读不出信息量，而真正该看的两个数——本轮共烧多少、上下文还剩多少空间——页面上根本没有；圆点与 ✓/✕ 也不表意，✓ 还同时承担"是工具调用"和"执行成功"两件事，且文本字符随平台字体度量漂基线。

### 实现方式

数字全部复用既有机制，不另起口径——轮末汇总取 trace.Request 的 In/Out（OnLLMCall 逐轮累计），占比与闸门取 ctxengine 的 EstimateTokens / Config().WindowTokens / ShouldArchive，压缩走同步的 Engine.Compact（与轮末自动归档同一条流水线）；CompactContext 与 Ask 抢同一把会话锁但用 TryLock，抢不到直接回「正在回复中」，并在压缩后补 pool.Save 落盘（Compact 只改内存会话）；治理未启用时快照只回 {enabled:false}，前端隐藏 chip。图标为内联 SVG + currentColor，不引图标库；顺手修掉 .ib-btn 无 background 导致深色 chip 吃浏览器默认按钮面、.pop-item 无 :disabled 态导致置灰项与可点项无区别，以及 .step-ico.ok/.fail 硬编码色改走 --danger 令牌。
