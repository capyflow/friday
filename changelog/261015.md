# 2026-10-15

## 待办表单标签被日期控件挤裁

- 现象：新增/编辑待办的「截止时间（本地，可选）」「提醒时间（本地，可选）」标签在窄窗口或平台字体度量不同（如 Windows 中易黑 + Windows 的 datetime 控件固有宽度）时，标签列宽度被 `datetime-local` 输入框绑架——文字溢出 label 盒子后被右侧「添加」按钮盖住，看起来像被截断；挤压更狠时日期框内容也会被裁。
- 修复（`web/src/style.css` `.panel form`）：label 列自带宽度下限（`flex: 1 1 180px; min-width: 180px`）并让输入框 `width: 100%` 填满 label——label 宽度由自身保证，不再依赖控件的固有宽度；行间距 `gap: 8px 10px`，放不下时整列换行而不是互相挤压。`TodoView.vue` 里三个 label 的 inline flex 样式与无效的 `w1` class（CSS 选择器是 `input.w1`，写在 label 上从未命中）随之删除，样式收敛到全局规则。
- 顺带删除两条无引用的死规则：`.st-cell`、`#tTimes { max-width: 90px }`（后者是典型的截断隐患，谁用谁踩）。
- 全库扫描：逐一核对了 web/src 全部视图/设置节与桌面外壳占位页的 nowrap/ellipsis/fixed-width 用法，其余省略号均为可展开的预览行（思考块、工具调用、轨迹摘要）或常规单行截断（用户名、TOC 摘要），属设计意图，未动。
- 验证：vite dev + 无头浏览器在 1100/1000/850/480px 四档宽度、深浅两主题下截图核对——表单要么单行放下、要么整列换行，任何档位都无文字被盖；带长文本待办的表格换行正常。`npm run check`（eslint + vitest）通过（system-notifications、native-status 两文件 11 例为存量环境失败，干净 HEAD 上同样失败，与本轮无关）。
