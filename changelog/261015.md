## 深色下 toast 文字看不见

- 现象：登录成功的「登录成功，欢迎回来 👋」气泡在深色下是一团近乎黑色的字压在近黑底上，只剩 emoji 能认。
- 根因：`#toast` 基础规则是 `background: var(--primary); color: var(--on-primary)`，深色覆盖只改了背景（`rgba(22,22,22,.92)` 炭灰玻璃）没改文字色。261014 深色去紫把 `--primary` 翻成亮灰反白、`--on-primary` 相应翻成 `#141414`，于是这条覆盖继承到了一个"给亮灰底用的深色文字"。同批改动的用户气泡（`html[data-theme="dark"] .mrow.user .bubble`）当时补了 `color: var(--fg)`，toast 漏了。
- 修复：深色 `#toast` 补 `color: var(--fg)`。`.err` 变体不设文字色、继承同一条，一并解决。全库核过 `--on-primary` 的其余 8 处用法，都是与 `background: var(--primary)` 成对出现的（深色下即亮灰底深字，本就是设计意图），没有第二处同类漏网。
- 验证：一次性 harness 截图核对深浅两色 × 普通/`.err` 四种组合（`/tmp/friday-icons/toast-{light,dark}.png`），浅色未受影响；`npm run build` 重建 webdist。

## 聊天时间线三处错位：两字成行、刷新丢块、轮末用量只剩一轮

- 现象（StepFun step-5-preview 实测）：① 每次回答开头都有一两个字的孤立一行（「我是」「基于」），
  下面再跟一个思考块与真正的正文；② 刷新后思考跑到回答**后面**，工具调用与每轮的耗时摘要全不见；
  ③ 轮末「本轮 · x+y tokens」只有当前这一次对话有，刷新后一行都不剩。
- 根因①（前端分块）：`pushThinking`/`pushText` 按「最后一块是什么类型」决定并入还是新起。
  网关把 `reasoning_content` 与 `content` 的分片**交错**下发（先吐几个字的正文、再补一段思考），

## 模型库：多模型配置 + 每模型上下文窗口与输入格式 + 聊天页快捷切换

- 动机：原「模型服务」只有一组 baseURL/model/密钥，换模型要整行重填；上下文窗口靠框架按模型名查表（step-5-preview 不在表里，静默落 128k 兜底）；模型是否支持图片没有任何声明——测试连接的结果只展示不落库，聊天页永远开放图片入口。拍板：模型库 + 单激活切换，聊天页加快捷切换入口；角色路由（摘要/主动任务用别的模型）本轮不做。
- 配置结构（`internal/config/config.go`）：新增 `ModelProfile`（name 唯一主键/baseURL/model/apiKeyEnv/apiKey/contextWindow/inputs）与 `ProviderConfig.{Active,Models,ContextWindow}`。**扁平字段仍是运行事实源**：激活条目在切换时"投影"到扁平字段（`projected := prev` 出发，条目未覆盖的维度沿用现状），`newProvider`/`/api/status` 等既有消费方零改动。`Models`/`Active`/`ContextWindow` 带 omitempty——yaml.v3 会把 nil 切片渲染成 `models: []`，不加了会污染所有 Marshal 出来的配置（runtime_regression 的 DeepEqual 对比磁盘就是这么炸出来的）。`Validate()` 补模型库规则（name 唯一、baseURL/model 非空、inputs ⊆ {text,image}、active 命中）；`ProviderConfig.ResolveAPIKey()` 从 `ProviderAPIKey()` 提取复用。`inputs` 空 = 全支持（兼容未声明能力的老配置，不因升级突然禁图）。
- 写盘（`UpdateProviderModels`）：yaml.Node 编辑保留注释，写 models 序列 + active + 扁平投影（contextWindow 用 `!!int` 节点——`setMappingKey` 打 `!!str` 标签，回读 int 直接炸）；`runtime.go` 快照深拷贝补 Models 与每条 Inputs。
- 热切换（`reload.go` 新增 `ReloadProviderModels`，仿 ReloadPersona 的 校验→cfg.Apply→Reconfigure→写盘→发布）：密钥继承（前端传空 + 旧库同名条目有 key → 沿用，"留空=保留"）；按变化范围决定重建量——投影后的 baseURL/model/生效密钥/窗口任一变了才重建引擎与 Agent，只编辑非激活条目或 inputs 声明时只落盘。库内切换不强制重填密钥（每条档案自带）。
- 窗口解析链（`context.go` Rebuild）：`context.windowTokens`（全局显式覆盖）> `provider.contextWindow`（激活条目投影）> 框架按模型名查表。`/api/status` 的 provider 增加 `inputs` 与 `contextWindow`（有效值）。
- 接口（`ext.go` + `admin.go`）：`GET /api/provider/models`（未建库时用扁平字段合成一条返回，前端无特例；密钥不回传只回 keySet）、`POST /api/provider/models`（全量保存+激活）、`POST /api/provider/activate`（聊天页轻量切换，复用同一内核）；legacy `POST /api/provider` 在库存在时把改动同步回激活条目，防两处不一致。
- 前端：`ProviderSettings.vue` 重塑为模型库 UI（该组件仅 ModelSection 一个消费方；行卡片 `.pm-row` 与 `.mcp-row` 同规格但独立类名，避免选择器互相污染）——每行 显示名/地址/模型名/密钥（留空=保留）/上下文窗口/图片输入复选/行内「测试」（勾了图片自动带 checkVision）/删除，radio 选激活，「生效中」徽标标记加载时已生效的条目；测试结果随字段编辑立即失效（`@input` 清 testMsg）。`ChatView` composer 左组新增模型 chip（与上下文 chip 同形，模型名 110px 截断），弹层列库点选即切换并刷新上下文占比，底部入口深链设置；「添加图片」按激活条目 inputs 置灰并说明，粘贴图片同样被拒；`type="number"` 的 v-model 给数值型，collect 里统一收成非负整数。
- 测试：`config_models_test.go`（写盘 round-trip 保留注释/扁平投影/二次覆盖、Validate 七种非法、inputs 语义、快照深拷贝）、`reload_models_test.go`（切换重建+投影落盘、密钥继承+非激活编辑不重建、仅窗口变化重建、五种非法拒绝且配置不动）、settings-modal（模型节默认拉 models 接口、行渲染、radio 换激活 + 保存 payload）、provider-settings.test.js 按新 UI 重写（加载渲染/行内校验/保存 payload 与密钥清空/行内测试与失效/删除回落/保存失败）、chat.test.js 新增模型 chip 三例（渲染与能力标注/activate 调用/图片置灰与粘贴拒绝）。Go 22 包全绿；web 全量 170 例，除存量环境失败（jsdom localStorage/matchMedia）外全过、eslint 干净。
