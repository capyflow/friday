## feat: 动态工作流 T0 竖切（wfhost 宿主 + internal/workflow 引擎）（`45860a4f2423`）

- Commit: `45860a4f2423d6b4eaf145d69078b2f7cccf0521`
- 时间: `2026-10-19T16:50:55+08:00`

### 变更内容

新增脚本沙箱宿主包 wfhost/（facade.d.ts 声明一期子集、check/run 两态 CLI、TS 类型检查与十条 lint 规则、ask<T> 的 JSON Schema 合成、vm 沙箱与换行帧 RPC）与 Go 侧 internal/workflow/（Frame 协议、宿主探测与进程监督、Check/Run、Executor 履约 world.run 与 files.*/git.*、12 个测试与 5 份 fixture），并落一期设计方案 docs/WORKFLOW.md 与 ROADMAP 第七节的四条定案。

### 修改原因

要把 ZCode 式「对话中生成的代码工作流」引入 Friday；脚本的副作用必须由 Go 侧统一履约，否则权限与用量记账会被旁路（ROADMAP 的"高危能力不得裸奔"底线），而跨界协议与进程监督是最容易返工的两层，需要先用一个竖切钉死，再铺确认卡与入口。

### 实现方式

引擎全在 Go、node 只做脚本沙箱（弃用进程内 goja 的实测依据记在 docs/WORKFLOW.md 第二节）；脚本编译进 async 函数体，使 declare/export/import 自动非法且诊断行号与原文一致；命令集靠 R1 静态枚举供初次确认整批批准；每个在途请求单独起 goroutine 应答以保持扇出并发，ctx 结束由看门狗直接杀宿主；files.*/git.* 拒绝绝对路径、.. 与符号链接，world.run 走固定 argv 并用 approval.DenyPatterns + vxexec.CommandDenyMatcher 兜红线；流程元数据头改用行注释以避开 */ 提前终止块注释的缺陷；新增依赖 github.com/bmatcuk/doublestar/v4（含 go.sum 与 wfhost/package-lock.json）。
