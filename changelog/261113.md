## fix(智能体): 会话时间线留档进投影，重启后过程行不再只剩正文

- 时间: `2026-11-13`

### 变更内容

工作区会话的每一轮会在投影里留一份「时间线留档」：这一轮的思考、工具调用与
正文按到达顺序存进投影（acp-threads.json）。Friday 重启后回放历史，过程行
（「N 次思考 · M 次工具调用」）与工具明细照旧在，不再只剩一段纯正文。

### 修改原因

思考与工具调用只经事件总线（内存环形缓冲）推给前端，进程一重启就全没了；
投影里原本只留这一轮的回答正文，回放出来是「纯结果」——过程行与工具明细
整段消失，看着像 agent 根本没干过活。主对话早就有这套留档（internal/admin
的 histBlock），工作区会话一直没跟上。

### 实现方式

- `internal/acp/blocks.go`（新增）：Block 类型（think/tool/text，形状与主聊天
  的 histBlock 刻意一致）与留档口径——连续思考/正文各自合成一块，同
  toolCallId 的工具调用原地更新（run → ok/fail），裁剪上限与主聊天同口径
  （思考 4000 / 正文 8000 / 工具 160）。
- `internal/acp/aggregate.go`：turnSink 在把内容投给前端的同一处留档（文本/
  思考按段、工具按 id 归并）；工具留档放在钩子判空之前——没有订阅端时也要
  留，否则重启后照样丢过程。轮末还停在 run 的工具按「已执行完」收口（与实时
  时间线的 closeRunningTools 同一口径），回放出来不会是一排永远转圈的圈。
- `internal/acp/manager.go`：Entry 加 blocks 字段随投影落盘，TurnResult 带
  这一轮的留档，轮末写进那条 assistant 消息。
- `web/src/blocks.js`：histBlocks() 提到共享处，主对话与工作区会话共用同一
  份映射；`ChatView.vue` 改用它。
- `web/src/components/WorkspaceView.vue`：回放历史时按留档还原时间线；没有
  留档的旧会话照旧只显示正文（不留档就不凭空画出过程）。
- 测试：轮末投影里有思考/工具/正文三块、重启重读投影后仍在、旧投影（没有
  blocks 字段）照旧能读；前端两条——带留档的历史渲染出过程行与工具行，没
  留档的旧会话只显示正文。

## feat(智能体): agent 装好之后，设置里能查登录态并就地认证

- 时间: `2026-11-13`

### 变更内容

设置 → 智能体里，每台 agent 卡片多一个「认证」按钮：点开是一个认证面板，
能查这台 agent 的登录态（已登录 / 未登录 / 状态未知）、看它声明了哪些认证
方式，并就地完成认证：

- **agent 型**：调 agent 自己的 ACP `authenticate` 方法；
- **env_var 型**：填密钥，写进该 agent 的环境变量（落 config.yaml 的
  `acp.agents[].env`），随进程注入后再认证；
- **terminal 型**：给出一条能直接执行的登录命令，配合「在终端里登录」按钮
  把命令送进内置终端（新开一条真 PTY 自动敲进去，人只管在浏览器里点确认）。

面板还给出该 agent 的登录指引、凭据文件线索（如 `~/.codex/auth.json`）与
「重新检测」。安装完一台 agent 会自动展开它的认证面板——装好十有八九还没
登录，别等人踩一次坑才知道。

### 修改原因

agent 装好之后能不能干活，取决于它自己的登录态（ChatGPT 账号、Google 账号、
API key…）。这份状态既不在 config.yaml 里，也不在 Friday 的会话层里：以前
只有「测试」按钮失败时，报错末尾才附一句「去终端登录」，属于事后诸葛亮——
人要先踩一次坑才知道这台还没登录。

### 实现方式

- `internal/acp/auth.go`（新增）：登录态三态判定与认证执行。判定按可信度
  排序：先信 agent 自己（`authenticate` 成功 = 已登录），再看环境变量型方法
  要的变量填了没，再看 HOME 下的凭据文件（CLI 类 agent 不声明 authMethods，
  凭据只落在 HOME 里），都看不出来就说「状态未知」——不硬猜「未登录」。
  拉不起来（命令写错、包没装）也不算「未登录」，只有报错本身指向登录态
  （stderr 命中登录/401 关键词）才这么判。
- ACP 的认证方式联合体在 SDK 里有个坑：`acp-go-sdk` 只按「报文里有没有
  type 字段」挑分支，有 type（哪怕值是 `agent`）又没带 vars 时会被判成
  terminal，没有 type 反而判成 agent。ACP 规范说「没有 type 即视为 agent」，
  所以归一层按规范纠正（既没 args 也没 env 的 terminal 变体一律当 agent 型）。
- `internal/acp/proc.go`：把 initialize 响应里的 `authMethods` 留在进程对象
  上（原来只留 loadSession）；登录指引表从「一句话」扩成「一句话 + 一条命令」，
  两个地方共用。
- `internal/admin/acp.go`：新增 `GET /api/acp/auth`（查登录态）与
  `POST /api/acp/auth`（执行认证）。env_var 型先把用户填的变量写进
  config.yaml 再认证——填完不落盘 = 下次拉起进程时凭据不在，等于没填。
- `web/src/components/settings/AcpSection.vue`：认证面板（状态徽章、认证方式
  列表、密钥输入框、登录指引、复制命令、在终端里登录）。
- `web/src/store.js` + `web/src/components/TerminalView.vue`：终端页支持
  接收一条命令并在新标签里自动敲进去（设置页「在终端里登录」走这条路）。
- 错误信息带上 agent 自己的 stderr 尾部：有的 agent 把登录链接印在自己的
  stderr 上，超时/失败时那句话要能看见。

## feat(智能体): 认证判定改成「本地信号优先」，codebuddy 这类 agent 说清登录方式

- 时间: `2026-11-13`

### 变更内容

认证面板的登录态判定与认证动作按实测结果调整：

- **判定顺序**：先用本地信号（agent 声明要的环境变量填了没、HOME 下有没有
  凭据文件、配置里有没有密钥），都命中不上才去问 agent 自己
  （`authenticate`）。原来反过来——先调 agent，那一步可能阻塞甚至当场
  拉起登录流程，探测阶段不该有副作用。
- **agent 不吭声 ≠ 未登录**：`authenticate` 请求收下不回应（codebuddy 就是
  这样，它把登录界面甩给人），这种只判「状态未知」，并提示按登录指引去
  终端登录，不再说成「未登录」。
- **探测最多试 3 个方式、每个 5 秒**：声明了多个登录方式的 agent 逐个试
  一遍既慢又多半失败。
- **认证动作超时的等待从 90 秒降到 15 秒**，超时后给出可执行的下一步
  （登录命令），而不是让人对着转圈等。
- **codebuddy 的登录方式写进指引**：它声明了四种（iOA / Google-Github /
  微信 / 企业域），面板逐条列出；凭据不在文件里（大概在钥匙串），所以本地
  探测不出登录态，只能问它。

### 修改原因

实测各家 agent 的行为差别很大，不调整判定就会给出误导结论：

- codebuddy 声明 4 个认证方式，但 `authenticate` 收下不回应——按老逻辑会
  判成「未登录」，而它其实把登录界面甩给了用户；
- claude 的 `claude-login` 是声明了却没实现（`Method not implemented`），
  正路同样是在终端里 `claude /login`；
- 已经登录的 agent（凭据文件在）不该因为 `authenticate` 失败而被判成未登录。

### 实现方式

- `internal/acp/auth.go`：`probeLoginState` 改为本地信号优先、agent 询问
  兜底；新增「agent 不回应 → 状态未知」与「最多试 N 个方式」；认证动作的
  超时文案带上该 agent 的登录命令；`loginGuides` 补 codebuddy 条目。
- `internal/acp/manager_test.go`：fake agent 支持「authenticate 不回应」。
- `internal/acp/auth_test.go`：本地信号优先于 authenticate、agent 不回应
  判未知、探测最多试几个方式、codebuddy 指引。

### 涉及文件

- `internal/acp/auth.go`
- `internal/acp/auth_test.go`
- `internal/acp/manager_test.go`

## feat(智能体): 给「只认环境变量」的 agent 补上填凭据的入口（codebuddy 这类）

## fix(智能体): 登录态判不准——改用「建一次会话」直接问 agent 自己

- 时间: `2026-11-13`

### 变更内容

登录态探测多了一道最硬的证据：**建一次会话**（session/new）。能建出会话
= 凭据确实可用；报 `Authentication required` = 没登录（agent 的原话原样
带回来）。codebuddy 这类把凭据放钥匙串的 agent，读不到文件也能判准。

面板同时给出取凭据的直达链接（codebuddy → API Key 管理页），登录指引写
清该走哪条路：终端里跑 `codebuddy` 后用 `/login` 走浏览器授权。

### 修改原因

「网页端登录了，但程序里读不到登录信息」这件事查清了，三条原因叠在一起：

1. **网页登录 ≠ CLI 凭据**。codebuddy 的 CLI 只认三种凭据：环境变量里的
   `CODEBUDDY_API_KEY` / `CODEBUDDY_AUTH_TOKEN`、settings.json 里的
   `apiKeyHelper`、终端里的 `/login`（凭据进 macOS 钥匙串）。网页版的
   登录会话跟 CLI 不相通。
2. **凭据不在文件里**。官方文档写明 macOS 下凭据存在**加密的钥匙串**，
   所以「读凭据文件」那套探测（`~/.codex/auth.json` 那种）对它是死的。
3. **它的 ACP `authenticate` 根本没实现**。实测发过去 45 秒不回应也不
   报错，stderr 全空——原来那套「调 authenticate 判登录态」的逻辑对它只能
   得到「状态未知」。

于是改用 agent 自己能回答的问题：让��建一次会话。能建出来就说明凭据可用
（哪怕我们读不到钥匙串）；建不出来且报鉴权错，就是没登录。

### 实现方式

- `internal/acp/auth.go`：新增 `probeSession`（建会话试探，25 秒上限）；
  探测顺序改为「本地信号 → authenticate → 建会话」；`AuthStatus` 增加
  `link`（取凭据地址）；`loginGuide` 增加 `link`，codebuddy/claude/
  gemini/codex 各自补上地址，codebuddy 的指引改写成「终端 `codebuddy` +
  /login 浏览器授权，或填 API Key」。
- `internal/acp/proc.go`：鉴权关键词补 `authentication`（agent 回的是
  "Authentication required"）。
- `internal/acp/manager_test.go`：fake agent 支持「建会话要鉴权」。
- `web/src/components/settings/AcpSection.vue`：面板渲染「去获取凭据」链接。

### 涉及文件

- `internal/acp/auth.go`
- `internal/acp/auth_test.go`
- `internal/acp/proc.go`
- `internal/acp/manager_test.go`
- `web/src/components/settings/AcpSection.vue`

## fix(界面): 聊天正文里的长路径不再被省略号截断

- 时间: `2026-11-13`

### 变更内容

正文里的路径现在完整显示：超长路径在气泡里折行，不再以「…」收尾；鼠标悬停
显示完整路径（原来只写「预览文件」）。文件预览抽屉顶部的路径同样改为折行。

### 修改原因

行内路径会被渲染成可点击的 file-chip（点开预览），而它的样式设了
`overflow: hidden; text-overflow: ellipsis; white-space: nowrap`——路径一
长就从尾巴截断。被吃掉的往往正是**文件名**：`/Users/.../photos-releas…`
看着像半个路径，用户没法照抄、也没法确认是哪个文件。路径是给人照着用的，
宁可折行也不能省略。

### 实现方式
