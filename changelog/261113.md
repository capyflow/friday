## fix(智能体): 会话时间线留档进投影，重启后过程行不再只剩正文

- 时间: `2026-11-13`

### 变更内容

工作区会话的每一轮会在投影里留一份「时间线留档」：这一轮的思考、工具调用与
正文按到达顺序存进投影（acp-threads.json）。Friday 重启后回放历史，过程行
（「N 次思考 · M 次工具调用」）与工具明细照旧在，不再只剩一段纯正文。

### 修改原因

思考与工具调用只经事件总线（内存环形缓冲）推给前端，进程一重启就全没了；
投影里原本只留这一轮的回答正文，回放出来是「纯结果」——过程行与工具明细
整段消失，看着像 agent 根本没干过活。主对话早就有这套留档（internal/admin
的 histBlock），工作区会话一直没跟上。

### 实现方式

- `internal/acp/blocks.go`（新增）：Block 类型（think/tool/text，形状与主聊天
  的 histBlock 刻意一致）与留档口径——连续思考/正文各自合成一块，同
  toolCallId 的工具调用原地更新（run → ok/fail），裁剪上限与主聊天同口径
  （思考 4000 / 正文 8000 / 工具 160）。
- `internal/acp/aggregate.go`：turnSink 在把内容投给前端的同一处留档（文本/
  思考按段、工具按 id 归并）；工具留档放在钩子判空之前——没有订阅端时也要
  留，否则重启后照样丢过程。轮末还停在 run 的工具按「已执行完」收口（与实时
  时间线的 closeRunningTools 同一口径），回放出来不会是一排永远转圈的圈。
- `internal/acp/manager.go`：Entry 加 blocks 字段随投影落盘，TurnResult 带
  这一轮的留档，轮末写进那条 assistant 消息。
- `web/src/blocks.js`：histBlocks() 提到共享处，主对话与工作区会话共用同一
  份映射；`ChatView.vue` 改用它。
- `web/src/components/WorkspaceView.vue`：回放历史时按留档还原时间线；没有
  留档的旧会话照旧只显示正文（不留档就不凭空画出过程）。
- 测试：轮末投影里有思考/工具/正文三块、重启重读投影后仍在、旧投影（没有
  blocks 字段）照旧能读；前端两条——带留档的历史渲染出过程行与工具行，没
  留档的旧会话只显示正文。

## fix(界面): 过程行内部不再套一层工具折叠

- 时间: `2026-11-13`

### 变更内容

过程行（「N 次思考 · M 次工具调用」）展开后，里面连续的工具调用不再收成
「执行工具 N 次」的叠，逐条平铺成行——外面已经汇总过次数，里面再折一层是
重复折叠。每条调用仍可单独展开看参数与结果。

### 修改原因

两层折叠叠在一起：「2 次思考 · 11 次工具调用」展开后又是「执行工具 5 次」
「执行工具 6 次」，想看其中某一条调用得连点三层。

### 实现方式

- `web/src/components/TimelineBlocks.vue`：过程行的成员渲染里，工具叠分支改成
  平铺（逐条 ToolStep），工具行与思考行同缩进；顶层只有工具序列、没有思考
  行时的那一层叠保留——那层是唯一一层折叠，不是重复。
- 测试：过程行展开后工具逐条平铺（`.proc-body` 里没有 `.tool-stack`）。

### 涉及文件

- `web/src/components/TimelineBlocks.vue`
- `web/tests/timeline-blocks.test.js`

## feat(智能体): agent 装好之后，设置里能查登录态并就地认证

- 时间: `2026-11-13`

### 变更内容

设置 → 智能体里，每台 agent 卡片多一个「认证」按钮：点开是一个认证面板，
能查这台 agent 的登录态（已登录 / 未登录 / 状态未知）、看它声明了哪些认证
方式，并就地完成认证：

- **agent 型**：调 agent 自己的 ACP `authenticate` 方法；
- **env_var 型**：填密钥，写进该 agent 的环境变量（落 config.yaml 的
  `acp.agents[].env`），随进程注入后再认证；
- **terminal 型**：给出一条能直接执行的登录命令，配合「在终端里登录」按钮
  把命令送进内置终端（新开一条真 PTY 自动敲进去，人只管在浏览器里点确认）。

面板还给出该 agent 的登录指引、凭据文件线索（如 `~/.codex/auth.json`）与
「重新检测」。安装完一台 agent 会自动展开它的认证面板——装好十有八九还没
登录，别等人踩一次坑才知道。

### 修改原因

agent 装好之后能不能干活，取决于它自己的登录态（ChatGPT 账号、Google 账号、
API key…）。这份状态既不在 config.yaml 里，也不在 Friday 的会话层里：以前
只有「测试」按钮失败时，报错末尾才附一句「去终端登录」，属于事后诸葛亮——
人要先踩一次坑才知道这台还没登录。

### 实现方式

- `internal/acp/auth.go`（新增）：登录态三态判定与认证执行。判定按可信度
  排序：先信 agent 自己（`authenticate` 成功 = 已登录），再看环境变量型方法
  要的变量填了没，再看 HOME 下的凭据文件（CLI 类 agent 不声明 authMethods，
  凭据只落在 HOME 里），都看不出来就说「状态未知」——不硬猜「未登录」。
  拉不起来（命令写错、包没装）也不算「未登录」，只有报错本身指向登录态
  （stderr 命中登录/401 关键词）才这么判。
- ACP 的认证方式联合体在 SDK 里有个坑：`acp-go-sdk` 只按「报文里有没有
  type 字段」挑分支，有 type（哪怕值是 `agent`）又没带 vars 时会被判成
  terminal，没有 type 反而判成 agent。ACP 规范说「没有 type 即视为 agent」，
  所以归一层按规范纠正（既没 args 也没 env 的 terminal 变体一律当 agent 型）。
- `internal/acp/proc.go`：把 initialize 响应里的 `authMethods` 留在进程对象
  上（原来只留 loadSession）；登录指引表从「一句话」扩成「一句话 + 一条命令」，
  两个地方共用。
- `internal/admin/acp.go`：新增 `GET /api/acp/auth`（查登录态）与
  `POST /api/acp/auth`（执行认证）。env_var 型先把用户填的变量写进
  config.yaml 再认证——填完不落盘 = 下次拉起进程时凭据不在，等于没填。
- `web/src/components/settings/AcpSection.vue`：认证面板（状态徽章、认证方式
  列表、密钥输入框、登录指引、复制命令、在终端里登录）。
- `web/src/store.js` + `web/src/components/TerminalView.vue`：终端页支持
  接收一条命令并在新标签里自动敲进去（设置页「在终端里登录」走这条路）。
- 错误信息带上 agent 自己的 stderr 尾部：有的 agent 把登录链接印在自己的
  stderr 上，超时/失败时那句话要能看见。

## fix(智能体): 内嵌目录里 codex / claude 的 npx 启动命令跑不起来

- 时间: `2026-11-13`

### 变更内容

内嵌可安装目录里的 codex 与 claude-code 两条，启动命令从
`npx -y <scoped 包>` 改成 `npx -y -p <scoped 包> <bin>`。

### 修改原因

scoped 包不能直接 `npx <包名>`：那样 npx 会去找一个名字带斜杠的命令，报
「sh: @agentclientprotocol/codex-acp: No such file or directory」，agent 秒退。
必须显式点名包里的 bin（codex-acp / claude-code-acp）。实测 `npx -y -p
@zed-industries/claude-code-acp claude-code-acp` 能正常起 ACP 服务并回
initialize 响应。

这条错命令还让「一键安装 codex」装出一台根本起不来的 agent：安装成功、
清单里也有一台，但一用就秒退。

### 实现方式

- `internal/acp/catalog.go`：两条内嵌目录模板改成 `npx -y -p <包> <bin>`。
- `internal/acp/catalog_test.go`：加一条守卫——目录里凡是 scoped 的 npx
  条目，都必须带 `-p` 且最后一段是包里的 bin 名。

### 涉及文件

- `internal/acp/catalog.go`
- `internal/acp/catalog_test.go`
