# 261111 变更记录

## fix(智能体): npx 型 agent 与 MCP 的 npm 包缓存收进数据目录

- 时间: `2026-11-11`

### 变更内容

包管理器拉起器（npx/npm/pnpm/yarn/deno/bunx/uvx/pipx…）拉起的 agent 与 MCP 服务器子进程，spawn 时注入 `npm_config_cache=<数据目录>/npm-cache`，包缓存（`_cacache` 与 `_npx` 物化目录）不再落在系统 `~/.npm`。

### 修改原因

261110 清 `~/.npm/_npx` 把本机全部 npx 型 agent 打瘫，还连带引发 MCP 重启风暴。缓存收进数据目录后，用户清系统 `~/.npm` 不再影响 Friday。

### 实现方式

判定表从 `internal/acp/manager.go` 下沉到 `internal/config/npmcache.go`（`IsPackageLauncher`），握手预算判定与 acp/MCP 两处 spawn 共用同一张表，不再各存一份。acp 私有的 `buildEnv` 换成导出的 `config.MergeEnv`；mcp 原来「有 env 就整份替换 + 追加」的写法也改用它——同名 key 原地覆盖、结果无重复 key（直接 append 会让覆盖对 node 系子进程静默失效）。配置里显式给的 `npm_config_cache` 仍优先：注释放 extra 层、`cfg.Env` 在其后覆盖。目录按内核 cwd（启动时已 chdir 到数据目录）取绝对路径，相对值会被 ACP 子进程的 cwd（工作区）解析、把缓存撒进用户项目；`MkdirAll` 失败只记日志，不挡 spawn。

### 涉及文件

- `internal/config/npmcache.go`
- `internal/config/npmcache_test.go`
- `internal/config/acp.go`
- `internal/acp/manager.go`
- `internal/acp/proc.go`
- `internal/acp/proc_test.go`
- `internal/mcp/client.go`

## fix(界面): 输入框切窗口回来不再塌成一行

- 时间: `2026-11-11`

### 变更内容

在智能体/聊天输入框里写了多行文字，切到别的窗口再切回来，输入框只剩 rows=1 的一行（文字还在，带内部滚动条），必须再敲一个键才撑开。现在回到窗口、页面重新可见、窗口缩放都会按内容重算一次高度。

### 实现方式

高度本来就是 ChatComposer 按 `scrollHeight` 写进 textarea 的内联样式，而重算只挂在 `input` 事件上——WebKit 在窗口失焦再回来时重排这条 textarea 会把内联高度丢掉，这类重排不触发 `input`，于是要等下一次敲键。改动三处：(1) `onMounted` 里 `nextTick(autoGrow)`，带草稿挂载（切页签回来）时直接撑开；(2) 挂 `window focus` / `resize` 与 `document visibilitychange` 三个时机补算，卸载时摘掉；(3) 值监听从"只在清空时回落"改成任何外部改值都重算——顺带修好两个同源问题：把排队消息取回编辑、切到另一个带草稿的会话时，回填的长文字同样只显示一行。`autoGrow` 新增可见性守卫（`getClientRects()` 为空就跳过），避免在 v-show 藏起来的页面上量到 0 高把框压扁。工作区里三处 `inputEl.value.style.height = 'auto'` 是引用了一个从未绑定的 ref 的死代码，删掉；回落一行现在由组件自己的监听负责。

### 涉及文件

- `web/src/components/ChatComposer.vue`
- `web/src/components/WorkspaceView.vue`
- `web/tests/chat-composer.test.js`

## fix(终端): 工作区终端不再弹「还没开过终端」的中转页，空态就是终端面板本身

- 时间: `2026-11-11`

### 变更内容

工作区右侧工具面板切到「终端」时，只要这条会话没开过终端，就会显示一个自造的
中转页：「这条会话还没开过终端。/ 在本会话主目录打开终端」，把真正的终端面板整个
盖住。这页过去还会在用户根本没点过终端的情况下凭空冒出来（刷新后工具面板停在终端
标签上，或切到另一条没开过终端的会话）。现在改成：终端面板照常渲染，从没开过终端
的会话直接显示面板自己的空态「按上方 + 新建一个终端。」——和终端页里手动关掉全部
终端后的样子一致。

顺带把「面板一打开就自动起一个 shell」改掉：工作区终端不再自作主张开进程，
由人按 + 才新建（新终端仍落在该会话自己的主目录）。独立的「终端」页保持原样，
进去就有一个终端可用。

### 修改原因

中转页是多出来的一层，等于把同一件事说两遍，还让人以为终端坏了；而且它出现的
时机（刷新、切会话）与用户动作无关，看着像故障。面板自己已经有空态和「新建」
按钮，够用了。

### 实现方式

`WorkspaceTools.vue`：删掉中转页，终端实例改为「访问过的会话都挂着」（watch 当前
会话 id 登记进 `termOpened`），当前会话的实例一直挂载并 v-show，切走也不卸载
（里面的 shell 照旧跑）。`pickTab('terminal')` 的特殊分支随之删掉——终端标签与其
余四个标签一样，点同一个标签再点一次收回成窄条。

`WorkspaceTerminal.vue`：`ensureTab()` 不再在「一个终端都没有」时自动 `openTab()`，
只在已有终端时重量尺寸、归还焦点；空态分支的注释同步改成「还没开过，或全被手动关了」。
两个文件的行头注释与 `web/tests` 里两条终端用例按新语义同步。

### 涉及文件

- `web/src/components/WorkspaceTools.vue`
- `web/src/components/WorkspaceTerminal.vue`
- `web/tests/workspace-terminal.test.js`
- `web/tests/workspace-view.test.js`
