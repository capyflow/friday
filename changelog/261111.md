## fix(智能体): npx 型 agent 与 MCP 的 npm 包缓存收进数据目录

- 时间: `2026-11-11`

### 变更内容

包管理器拉起器（npx/npm/pnpm/yarn/deno/bunx/uvx/pipx…）拉起的 agent 与 MCP 服务器子进程，spawn 时注入 `npm_config_cache=<数据目录>/npm-cache`，包缓存（`_cacache` 与 `_npx` 物化目录）不再落在系统 `~/.npm`。

### 修改原因

261110 清 `~/.npm/_npx` 把本机全部 npx 型 agent 打瘫，还连带引发 MCP 重启风暴。缓存收进数据目录后，用户清系统 `~/.npm` 不再影响 Friday。

### 实现方式

判定表从 `internal/acp/manager.go` 下沉到 `internal/config/npmcache.go`（`IsPackageLauncher`），握手预算判定与 acp/MCP 两处 spawn 共用同一张表，不再各存一份。acp 私有的 `buildEnv` 换成导出的 `config.MergeEnv`；mcp 原来「有 env 就整份替换 + 追加」的写法也改用它——同名 key 原地覆盖、结果无重复 key（直接 append 会让覆盖对 node 系子进程静默失效）。配置里显式给的 `npm_config_cache` 仍优先：注释放 extra 层、`cfg.Env` 在其后覆盖。目录按内核 cwd（启动时已 chdir 到数据目录）取绝对路径，相对值会被 ACP 子进程的 cwd（工作区）解析、把缓存撒进用户项目；`MkdirAll` 失败只记日志，不挡 spawn。

- `internal/config/acp.go`
- `internal/acp/manager.go`
- `internal/acp/proc.go`

## fix(界面): 输入框切窗口回来不再塌成一行

- 时间: `2026-11-11`

### 变更内容

在智能体/聊天输入框里写了多行文字，切到别的窗口再切回来，输入框只剩 rows=1 的一行（文字还在，带内部滚动条），必须再敲一个键才撑开。现在回到窗口、页面重新可见、窗口缩放都会按内容重算一次高度。

### 实现方式

高度本来就是 ChatComposer 按 `scrollHeight` 写进 textarea 的内联样式，而重算只挂在 `input` 事件上——WebKit 在窗口失焦再回来时重排这条 textarea 会把内联高度丢掉，这类重排不触发 `input`，于是要等下一次敲键。改动三处：(1) `onMounted` 里 `nextTick(autoGrow)`，带草稿挂载（切页签回来）时直接撑开；(2) 挂 `window focus` / `resize` 与 `document visibilitychange` 三个时机补算，卸载时摘掉；(3) 值监听从"只在清空时回落"改成任何外部改值都重算——顺带修好两个同源问题：把排队消息取回编辑、切到另一个带草稿的会话时，回填的长文字同样只显示一行。`autoGrow` 新增可见性守卫（`getClientRects()` 为空就跳过），避免在 v-show 藏起来的页面上量到 0 高把框压扁。工作区里三处 `inputEl.value.style.height = 'auto'` 是引用了一个从未绑定的 ref 的死代码，删掉；回落一行现在由组件自己的监听负责。

## fix(终端): 工作区终端不再弹「还没开过终端」的中转页，空态就是终端面板本身

- 时间: `2026-11-11`

### 变更内容

工作区右侧工具面板切到「终端」时，只要这条会话没开过终端，就会显示一个自造的
中转页：「这条会话还没开过终端。/ 在本会话主目录打开终端」，把真正的终端面板整个
盖住。这页过去还会在用户根本没点过终端的情况下凭空冒出来（刷新后工具面板停在终端
标签上，或切到另一条没开过终端的会话）。现在改成：终端面板照常渲染，从没开过终端
的会话直接显示面板自己的空态「按上方 + 新建一个终端。」——和终端页里手动关掉全部
终端后的样子一致。

顺带把「面板一打开就自动起一个 shell」改掉：工作区终端不再自作主张开进程，
由人按 + 才新建（新终端仍落在该会话自己的主目录）。独立的「终端」页保持原样，
进去就有一个终端可用。

### 修改原因

中转页是多出来的一层，等于把同一件事说两遍，还让人以为终端坏了；而且它出现的
时机（刷新、切会话）与用户动作无关，看着像故障。面板自己已经有空态和「新建」
按钮，够用了。

### 实现方式

`WorkspaceTools.vue`：删掉中转页，终端实例改为「访问过的会话都挂着」（watch 当前
会话 id 登记进 `termOpened`），当前会话的实例一直挂载并 v-show，切走也不卸载
（里面的 shell 照旧跑）。`pickTab('terminal')` 的特殊分支随之删掉——终端标签与其
余四个标签一样，点同一个标签再点一次收回成窄条。

`WorkspaceTerminal.vue`：`ensureTab()` 不再在「一个终端都没有」时自动 `openTab()`，
只在已有终端时重量尺寸、归还焦点；空态分支的注释同步改成「还没开过，或全被手动关了」。
两个文件的行头注释与 `web/tests` 里两条终端用例按新语义同步。

### 涉及文件

- `web/src/components/WorkspaceTools.vue`
- `web/src/components/WorkspaceTerminal.vue`
- `web/tests/workspace-terminal.test.js`
- `web/tests/workspace-view.test.js`
## feat(智能体): 内置 agent 具备独立编码能力（检索 / 只读 git / 批量编辑 / 命令工作目录对齐）

- 时间: `2026-11-11`

### 变更内容

内置 Friday（工作区里选 agent=内置 friday 的那条）此前只有管家的工具面：没有代码检索、
没有 git 视角、改多处要一轮轮 edit_file、命令还一律落在进程临时目录——`go test ./...`
`npm test` `pytest` 在项目里根本跑不起来（每条命令都得自己 cd，忘了就是在空目录里跑出
一个「没有测试文件」的假绿）。这轮把编码面补齐，让它不依赖 codex/claude/opencode 也能
自己把活干完：

- 新增 `search_code`：按正则（Go 语法）或字面量（`fixed=true`）搜文件内容，返回
  `路径:行号: 内容`；支持 `path` 根目录、`glob` 文件名过滤、`ignore_case`、`max_results`。
  跳过 `.git`/`node_modules`/`dist` 等依赖与构建目录，跳过二进制与 >2MB 文件。
- 新增 `find_files`：按 glob 找文件（`**` 跨目录、`*`/`?` 单层通配），返回相对路径。
- 新增只读 git 三件套 `git_status` / `git_diff` / `git_log`：从会话工作目录往上找仓库根，
  看当前分支与未提交改动、看 diff、看最近提交。写操作（commit/checkout/reset）仍留给用户在
  界面上点，不给模型。
- 新增 `edit_files`：一次改多处、多个文件。old 必须在目标文件里恰好出现一次（多处匹配整批
  拒绝），先全部校验通过再落盘，落盘中途失败回滚已写文件；confirm 模式下按整批投一张审批卡。
- `exec_command` 工作目录改为**本次会话的工作目录**（此前固定是进程临时目录），并新增 `cwd`
  参数；长输出截断从「只留开头」改成「保留头尾 + 标注省略量」——测试失败用例、编译错误都在
  末尾，只留开头等于把最该看的丢掉。
- 带项目目录的会话（工作区/工作模式）自动注入一段编码守则：先搜再改、改前先读、改动要小而准、
  动手前先看 git 现状、改完要跑验证并如实报结果。

### 修改原因

Friday 的产品路线是「跨 agent 宿主」：编码活原本外包给 codex/claude/opencode，内置 agent 只做
兜底。但兜底不等于不能用——用户明确要求内置 friday 本身就要有真正的工作能力，在没有外部
agent 时也能独立完成需求。上面这几项正是此前挡住这件事的硬缺口：不能检索就找不到代码，不能
看 git 就不知道现状，改多处只能串行，而命令不在项目目录里等于所有验证都不可信。

### 实现方式

检索与 git 自己实现，不引外部依赖（用户的机器上不一定装了 ripgrep，装了就多一条外部依赖，
没装就是工具直接不可用）：Go 正则 + `filepath.WalkDir` 遍历，glob 模式翻正则处理 `**`；git 走
`git` 子命令，只读、固定参数表（用户传的路径一律放在 `--` 之后）。`edit_files` 复用既有的
`FileTools.resolve`（允许根 + 软链逃逸防护）与 `backupAndWrite`（写前备份 .bak、失败还原）。
`exec_command` 改成 Friday 自持实现，权限语义不变：`PermissionMatchers` 仍透传框架的
`CommandMatcher`/`CommandDenyMatcher`，白名单/黑名单判定照旧在 Checker 里做。

新工具全部进了 `passThroughTools` 直通名单（与 read_file/write_file 同列）：否则 confirm 模式下
每次调用都会弹审批卡。其中 `edit_files` 的写操作仍走自己的 `approval.Queue`（整批一张卡）。

## feat(智能体): 文件生命周期、子任务派发与计划下沉（内置 agent 独立干活能力的第二批）

- 时间: `2026-11-11`

### 变更内容

接着上一批的编码面（检索 / 只读 git / 批量编辑 / exec 工作目录），这批补上「真实任务里必然遇到」的三件事：

- **文件生命周期**：新增 `move_file`（改名/移动）与 `delete_file`（删除）。此前内置 agent 只能靠
  `exec_command` 的 mv/rm 改文件名或删文件——要走审批、rm -rf 还被黑名单兜底，真实编码任务里经常卡住。
  `move_file` 的目标已存在时**在任何写动作之前**就拒绝（源不会因此丢失），`overwrite=true` 时旧目标先备份成
  `<to>.bak`；`delete_file` **不做硬删除**，文件移入回收站（系统临时目录下的 friday-trash，原子防撞名），
  返回值给出完整路径与恢复方法。软链移动/删除的是链接本身，不是它指向的文件。
- **子任务派发**：新增 `delegate_task`。主会话把一个自足的小任务派到隔离子会话（独立上下文，可并行），
  适合「摸清某块代码」「同时查几处」这类互不相干的调查。子任务默认只读（可检索、可读文件、可跑只读命令），
  跑完即清（不往 session.json 里堆），且不能再派子任务（嵌套上限 1 层，挡住递归烧预算）。
- **计划下沉**：新增 `create_plan`，agent 可以自己列步骤并按步执行。计划记着发起时的工作目录，
  `plan.Runner` 执行每一步时把该目录挂到 ctx 上——于是每一步的文件读写、命令与 AGENTS.md 注入都落在
  同一个项目里（此前网页发起的计划没有目录概念，步骤落在默认目录）。每步仍是一条独立轨迹、一份独立成本，
  进度在「自动化 → 计划」页看得见、随时能暂停或取消。

### 修改原因

工具齐了、纪律也补了，但内置 agent 仍然缺三样真实干活要用的东西：改文件名与删文件（否则只能去撞命令黑名单）、
把互不相干的调查并行出去（否则只能串行等三次）、以及把多步活儿按步骤推进（否则一步说太多、中途断了接不上）。
这三样补上后，「内置 friday 在没有外部 agent 时也能独立完成需求」才算真正成立。

### 实现方式

`move_file`/`delete_file` 放在 internal/tools（与其它文件工具同套允许根校验、软链逃逸防护与审批队列），
跨设备移动用 EXDEV 兜底（复制内容 + 保留权限位 + 删源）。`delegate_task` 放在 internal/agent：
Brain.Delegate 起一条 `sub-<父key>-<序号>` 的子会话（上下文隔离、跑完即清），嵌套深度走 ctx 标记。
`create_plan` 放在 internal/plan（internal/plan 已经依赖 internal/agent，反向依赖会成环），
由 cmd/robot/main.go 装配时注册。plan.Plan 增加 `Dir` 字段，Runner 执行每一步时用 workdir.With 挂上。

## feat(同步): 桌面端与手机端双端实时同步（agent 的回复两端同时可见）

- 时间: `2026-11-11`

### 变更内容

手机端问 agent 时，桌面端那边纹丝不动，必须手动刷新才看得到；桌面端正在生成时手机端再提问，那一端会一直卡在「思考中」永不返回，且一端按「停止」可能停到另一端正在跑的那一轮。这轮把「一轮对话」从 HTTP 连接里解耦成内核里的一个 turn 实体，两端都从同一条事件流读，agent 的回复在两端同时可见。

- **新增会话事件总线**（`internal/eventbus`）：按会话 key 路由，主会话 `web` 与 ACP 线程 `acp:<threadID>` 共用同一个实例。每会话保留 200 条环形缓冲，断线重连带 `since` 回来补发；缺口补不齐就明说「请全量重拉」，不假装事件是连续的。
- **提交与订阅分离**：`POST /api/chat` 与 `POST /api/acp/threads/:id/chat` 改成提交式，立刻返回 `{turnId, status, seq, session}`，这一轮在后台跑，增量/思考/步骤/收尾全部经事件总线广播。新增 `GET /api/events/stream?session=...&since=N` 订阅端点，桌面端、快捷面板、手机端、工作区四处前端统一走它。
- **同会话并发提问不再静默阻塞**：主会话加 FIFO 队列（先进先出，上限 20 条，排队超 10 分钟自动丢弃），撞忙时返回 `202 {status:"queued", position:N}`，前端显示「排队中 · 第 N 位」，另一端也看得见「手机端排队中」。工作区（ACP）沿用它既有的前端队列（`enqueue`/`pumpQueue`，支持编辑/删除/暂停），后端撞忙时只回 `202`，不叠第二套队列。
- **修掉「停止停错对象」的真 bug**：`runs` 从 `map[key]*chatRun` 改成 `map[key]map[turnId]*chatRun`，`POST /api/chat/stop` 与 ACP 的 stop 都要求带 `turnId`（必填，不带就明确报错，不猜）。turnId 由时间戳加进程内自增号组成，避免并发下撞号。
- **「关闭页面 = 中止生成」的语义废弃**：现在只有显式 stop 才停。页面关闭、断网、切窗口都不影响这一轮跑完，结果照常广播给所有订阅者——这是移动端后台化与桌面端切窗口的前提。
- **前端四处视图统一事件驱动渲染**：新增 `web/src/events.js`（订阅客户端：重连、`seq` 续传、缺口检测）与 `web/src/turnevents.js`（事件到时间线的共享翻译层，桌面端与移动端复用同一份，两端渲染必然一致）。消息气泡按 `turnId` 归属，自己发的消息不重复显示，别端发的标「来自手机端」。

### 修改原因

数据本来就是共享的：桌面端与手机端连的是同一个内核进程、同一份 `session.json`。桌面端看不到不是因为没存，而是因为 SSE 帧只写给发起请求的那条连接——别的客户端没有通道能收到。并发提问的「卡在思考中」也是同一个病根：Brain 里的 per-key 锁静默阻塞，连接建好了却一帧不发。

### 实现方式

契约见 [docs/EVENTS-API.md](docs/EVENTS-API.md)，设计见 [docs/MULTI-DEVICE-SYNC.md](docs/MULTI-DEVICE-SYNC.md)。前端不再自己建 SSE 连接消费帧，改为订阅 `/api/events/stream`；发起端与另一端走**完全相同**的读取与渲染路径，因此不会出现「两端显示成两个样子」。`EventSource` 不能带自定义 Authorization 头，所以该端点用 `wrapMedia` 鉴权（token 走 `?token=`，与通知长链接同一套）。
