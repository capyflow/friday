### 变更内容

MCP 服务器从整页表单改成一台一张卡（与设置 → 工具同一套卡片外壳），字段表单收进卡片里按需摊开：点头部那一行（图标 / 名称 / 摘要）展开，再点一次收回。头部不再放「配置」按钮，换成「更多」：重连与删除收进悬浮菜单，卡片收起时也能用。展开区底部只留「取消 / 保存」，整组靠右、取消在左、保存在最右。「＋ 添加服务器」移到列表右上角，位置固定，不再随列表长度跑到底部。每张卡的保存仍只提交这一张（其余按上次保存的值原样带上），改 A 不会把 B 没保存的草稿一起写进去。

### 修改原因

服务器一多，整页表单就得上下滚着找那一台；底部那个「＋ 添加服务器」还会随列表长度一路下沉，配置第三台时得先滚到底。删除与重连和保存挤在同一行，看着像「这一张卡的三个动作」，实际它们改的是「这台服务器」而不是「这张表单」。

### 实现方式

卡片头部整行做成一个真正的展开开关（图标 + 名称摘要 + 一个方向指示的 button，带 aria-expanded / aria-controls），右侧另挂「更多」按钮——菜单外壳沿用工作区与智能体列表那套行内菜单（.ws-menu-wrap + .ws-menu），实底、暗色自适配、危险项红色，不再新造一份样式；菜单一次只开一个，点菜单项 / 点外面 / 按 Esc 都收起，Esc 走 stopImmediatePropagation 只收菜单、不连带关掉整层设置弹窗；列表被刷新时菜单自动关闭，避免旧行号指到别的卡；没起名字的服务器「重连」置灰、「删除」仍可点。字段表单拆成 McpFields 组件，展开用 v-show（收起不丢正在输入的内容）。

## fix: 权限模式与附件在回复中也能改，切换不再挂起（`b3e2eebbeab0`）

- Commit: `b3e2eebbeab08209af4a6867692b3dbfc00d50bc`
- 时间: `2026-11-03T18:57:22+08:00`

### 变更内容

回复中小五时，权限 chip 与加号是灰的：切换走 brain.Reconfigure，而一轮对话从 Ask 进函数到 ag.Ask() 跑完一直持着 brain.rw 的读锁，重建 Agent 要等本轮结束——请求被挂到本轮跑完（本轮用的也还是旧档位）；设置页那条入口同样会挂，因为它也没判断 busy。加号那侧则被 addImageFiles / setMode / fill 的 busy 判断一起拦下。现在：权限 chip 与加号只在「清历史中」才禁用；权限切换在回复中会多给一句「编辑免审已即时生效，命令审批档位在当前审批答完后跟上」；加号弹层里「添加图片」回复中可用（附件挂到下一条消息并说明，也能撤回），「计划 / 目标 / 定时提醒 / 新建待办」仍禁用但带 title 说明——它们要写进回复中不可输入的输入框。

### 修改原因

权限档位是全局设置，回复中想从「确认」切到「自动编辑」正是最需要它的时刻（正被审批卡片卡住）；而切换实现把整次请求挂到本轮结束，等于「能点但没用」。附件同理：回复中先选好图、这轮跑完再发，本是顺手的事。

### 实现方式

后端改成分层生效：切档不再重建 Agent，改为先写回 config.yaml、更新配置快照、立刻翻转审批队列的编辑免审标记（acceptEdits/fullAccess 下 write/edit/mcp_edit 的内部审批当场放行，正在进行的这一轮也算数），再对活着的权限 Checker 做一次 SetMode——SetMode 放后台执行，因为框架 Checker 的锁贯穿整次判定（含网页审批问询），同步做会把这次请求也挂住，有审批卡正等人答时新档位在那张卡答完之后跟上。模式映射抽成 checkerMode 一个函数，建 Checker 与切档两处共用同一口径；每次 Build 出的 Checker 按审批队列记进 liveCheckers，切档据此定位活 Checker，查不到时才退回重建 Agent 的老路。前端去掉两个按钮的 busy 置灰，附件链路（addImageFiles / removePreview）放开 busy 判断并在预览条说明「图片挂在下一条消息上」。

## feat: 脚本与中间产物默认落系统临时目录，跑完自己删（`eee5df3637dc`）

- Commit: `eee5df3637dca3879eb21401c953ae3931e03e2f`
- 时间: `2026-11-03T18:57:34+08:00`

### 变更内容

agent 写脚本时落在数据目录根下、跑完也不删：桌面模式下进程 cwd 就是数据目录，exec_command 沿用进程 cwd，write_file 的白名单默认也只有数据目录那一处。现在脚本先在临时目录下造一个本次专用的子目录（macOS/Linux 用 mktemp -d，Windows 在 %TEMP% 下新建），用绝对路径引用，跑完连子目录一起删；产物（报告、导出、中间数据）用户没指定去处时也放临时目录并告知路径，只有用户明确说了位置、或产物本身要长期保留，才写到临时目录以外。exec_command 不再继承进程 cwd，改用本次运行的临时工作目录（0700），相对路径写出的文件落在那儿。

### 修改原因

数据目录是长期资产，脚本和中间产物留在里面会越积越多；而临时目录由系统兜底清理——macOS 的 /usr/libexec/tmp_cleaner 由 launchd 每天 0 点跑一遍，清掉 /tmp 下 3 天没访问过的文件（子目录里的文件一并清），空目录随后删除。

### 实现方式

提示词的【文件与命令】新增第 4 条写清临时目录约定；internal/agent/scratch.go 负责本次运行的临时工作目录（/tmp 下 0700 的独立子目录，启动时顺带清掉上次留下、超过 24 小时的同名目录）；config 侧抽出 TempDirs（白名单放行清单，macOS/Linux 是 /tmp 并额外带上用户私有 TMPDIR，Windows 是 %TEMP%）与 TempDirBase（临时工作目录的父目录）两处出口，白名单、exec 工作目录与旧目录清理共用同一口径，相对路径解析规则不变。
