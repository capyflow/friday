## fix: 聊天时间线按轮次归并块，历史投影先思考后回答并回显每轮用量（`25b618134cba`）

- Commit: `25b618134cba7ad348a2840e7066907b39ea6948`
- 时间: `2026-10-16T10:42:07+08:00`

### 变更内容

修掉 StepFun 实测暴露的三处错位——回答开头的一两个字被切成孤立碎行、刷新后思考块跑到回答之后且工具调用与每轮耗时摘要全部消失、轮末「本轮 · x+y tokens」只活在当前这一次对话里；现改为按 LLM 轮次归并块，历史投影固定 think→text，并把每轮用量配回对应的回答消息。

### 修改原因

网关会把 reasoning_content 与 content 的分片交错下发，旧的 pushThinking/pushText 按「最后一块是什么类型」决定并入还是新起，交错点两侧各起一块就把回答切碎了；provider 在流结束时按 text→thinking 次序 append Content，historyItems 照 Content 原序投影，顺序与实时时间线不一致；turn 只随 SSE done 帧下发、历史接口不带，刷新后用户看不到任何每轮成本。

### 实现方式

前端新增 blockIndex(m, kind) 在本轮范围内找块，m.round 由 round 事件与工具调用 run 推进（工具调用是轮次边界，不跨工具合并文本），本轮尚无思考块而正文已在写时新块插到正文前，liveThink/cursorOn 随之改判「是不是本轮那一块」；后端 historyItems 对每条 assistant 消息固定先输出 think 块再输出 text/图片块，histItem 新增 turn 字段，attachTurnUsage 复用 trace.List 的会话升序轨迹先按提问原文配对、配不上再按回答兜底（技能与自定义指令会改写提问文本），键取去空白后前 64 个 rune、同键从最近一轮往前配且一条轨迹只配一次；用量口径收口到 trace.TurnUsage 与 (*Request).Usage()，SSE done 帧与历史回显走同一出口，Ended 未落的一轮 ms 缺省由前端省略耗时段；web/tests/chat.test.js 补 4 例、internal/admin/ext_test.go 补 TestHistoryItemsOrdersThinkingBeforeText 与 TestAttachTurnUsage。

## feat: 侧栏瘦身三页收进设置，模型库支持多模型/窗口/输入格式与聊天快捷切换（`9a6afef0ac64`）

- Commit: `9a6afef0ac646dca2db13d2c04d3d4b8fddf0827`
- 时间: `2026-10-16T00:09:38+08:00`

### 变更内容

运行状态/调用轨迹/记忆三页收进设置弹窗（新增「运行观测」组、记忆入「数据与系统」，侧栏只留聊天/自动化/待办/通知），别的页面经 store.settingsSection 深链定位（自动化「查看执行轮次」与聊天菜单「调用轨迹」带会话过滤跳转）；「设置 → 模型服务」重塑为模型库——多条模型档案（地址/密钥/上下文窗口/输入格式）radio 选激活、行卡片收成一行摘要点击展开编辑，保存即热生效并写回 config.yaml；聊天 composer 新增模型 chip 点选即切换，激活条目不支持图片时聊天页图片入口置灰。

### 修改原因

三页是低频观测/内容页而侧栏只剩高频项更安静（用户拍板的收法）；原模型服务单组 baseURL/model 换模型要整行重填，上下文窗口靠框架按模型名查表（step-5-preview 不在表里静默落 128k），模型是否支持图片无声明导致图片入口恒开。

### 实现方式

扁平字段仍是运行事实源，激活条目切换时投影到扁平字段（ReloadProviderModels 按变化范围决定重建量：地址/模型/密钥/窗口变才重建引擎与 Agent，纯列表编辑只落盘）；窗口解析链 context.windowTokens > provider.contextWindow > 框架查表；密钥留空沿用该条目已存值；ProviderConfig 新字段带 omitempty（yaml.v3 会把 nil 切片渲染成 models: [] 污染 Marshal）。Go 22 包全绿、web 170 例除本机 jsdom 存量环境失败外全过、eslint 干净。
