# 261110 变更记录

## feat(界面): 新建会话改为弹窗，可选 agent 并预设标题

- 时间: `2026-11-10`

### 变更内容

桌面端在工作区里点「新建会话」从左栏内联表单改为居中弹窗：选智能体工具、可预设会话标题（留空自动取首条消息）。弹窗沿用既有 dialog 样式（Esc/点遮罩取消，标题框回车直接创建，打开即聚焦标题框），内置 Friday 的说明与主目录提示照旧保留。

### 修改原因

原来的内联表单塞在左栏工作区行里，宽度窄、只能选 agent 不能预设标题（手机端早就有这能力，后端 `POST /api/acp/threads` 本就收 `title`），两端交互不一致。

### 实现方式

`WorkspaceView` 移除 `.ws-session-form` 内联块，新增 Teleport 弹窗（`sessionFor` 驱动，与重命名/删除确认同一套 `dlg-*` 样式）：`sessionForm` 增加 `title` 字段随 POST 提交；`openSessionForm` 重置标题并 `nextTick` 聚焦输入框；新增 `onSessionEnter`（中文输入法组词中的回车不触发）。清掉不再使用的 `.ws-session-form` / `.ws-session-hint` 样式。

### 涉及文件

- `web/src/components/WorkspaceView.vue`
- `web/src/style.css`
- `web/tests/workspace-view.test.js`

## fix(移动端): 项目与会话列表按最近活动倒序

- 时间: `2026-11-10`

### 变更内容

手机端项目列表与项目内会话列表改为按最近活跃倒序（与桌面端一致）：刚活跃过的会话排最前，项目列表按组内最新会话活动排（没有会话的项目退回工作区自身时间），置顶项目优先。

### 修改原因

接口 `/api/acp/threads` 按投影文件里的创建顺序返回会话（`Manager.List` 遍历 `m.order`），移动端之前直接按这个顺序渲染，老会话永远沉在下面、新会话追加在末尾，看起来是乱序；桌面端 `WorkspaceView` 早已按 `updatedAt` 倒序排。

### 实现方式

`MobileThreads` 新增 `wsThreads`（当前项目会话按 `updatedAt` 倒序）与 `orderedWorkspaces`（置顶优先 + `wsActivity` 倒序）两个 computed，模板改为遍历排序后的列表；排序口径与桌面端 `WorkspaceView.vue` 完全一致。补两个测试用例覆盖「创建顺序 ≠ 活跃顺序」的场景。

### 涉及文件

- `web/src/mobile/MobileThreads.vue`
- `web/tests/mobile-threads.test.js`

## feat(界面/工作区): 工具面板收掉内部标签行与验证入口，终端撑满面板

- 时间: `2026-11-10`

### 变更内容

工作区右侧统一工具面板顶部不再重复一排「终端 / 文件 / 改动 / Git 管理 / 项目记忆 / 验证」文字标签，切工具只走右侧常驻图标条；「验证」入口从工具栏去掉。嵌在面板里的终端改为撑满整块高度，不再只占上半截。

### 修改原因

图标条本来就在旁边，面板里再排一排文字入口是重复；窗口窄时那排还会横向滚动。验证入口按用户要求撤掉。终端原来按内容高度排（约 24 行），面板下半截留白，看起来只占了半页。

### 实现方式

`WorkspaceTools` 删除 `.ag-tools-tabs` 那一段与 `verify` 标签，头部只剩标题和展开/收起按钮（标题 `flex:1` 把按钮推到右侧）。终端是列向 flex 里的直接子项，补 `.ag-tools-pane > .wt-panel { flex:1; min-height:0; width:100% }`，让 xterm 拿到整块高度后再 fit。

### 涉及文件

- `web/src/components/WorkspaceTools.vue`
- `web/src/style.css`
- `web/tests/workspace-view.test.js`

## feat(移动端): 会话里可以改模型 / 思考强度 / 审批档位

- 时间: `2026-11-10`

### 变更内容

手机端的智能体会话在输入框上方新增一行配置 chips：模型、思考强度、审批档位（agent 报什么显示什么）。点 chip 从底部弹出选项列表，选完即生效；回答进行中不可切换。主会话没有会话级配置，整行不出现。

### 修改原因

手机端建完会话只能发消息，改模型/档位还得回电脑，与桌面端的会话能力不一致。

### 实现方式

复用桌面同一份 `GET/POST /api/acp/threads/:id/options` 能力清单：`MobileChat` 在选中线程时拉取、轮末再刷新一次；chips 横向滚动排在输入框上方，选项走 `m-sheet` 底部弹层（与新建会话/项目设置同一套样式）。

### 涉及文件

- `web/src/mobile/MobileChat.vue`
- `web/src/mobile/mobile.css`
- `web/tests/mobile-chat.test.js`

## docs: AGENTS.md 固化打包签名要求，README 增打包必读提示

- 时间: `2026-11-10`

### 变更内容

新增仓库根 `AGENTS.md`（给 AI 助手与新成员的工作须知），把「每次打包前必读
desktop/README.md 的 macOS 正确打包流程」固化为最高优先级条目：只用脚本打包
（日常发版 = ad-hoc 完整签名 + `verify-macos.sh` 验收），发布说明必须写明签名
状态与放行命令；Developer ID + 公证（`--macos-release`）定位为凭据就绪后的
升级路径，缺证书不是打包失败。README 的「手机端」之后新增「桌面打包与发布
（重要）」一节指向同一流程。另把本机运行时文件 `auth-key`（内核 JWT 密钥）
与 `node_modules/` 加入 .gitignore。

### 修改原因

打包签名要求此前只写在 desktop/README.md 深处，代理/新人凭记忆打包容易跳过；
用户要求在 README 或 AGENTS.md 层面重点说明，保证每次打包都先看文档。0.4.4 起
的实际发版走 ad-hoc 完整签名并在发布说明标注放行方式，表述需与之一致。

### 实现方式

AGENTS.md 分「打包与发布」与「其他约定」两段：前者列四条硬性检查（Developer ID
签名、禁发 ad-hoc、证书预检、verify-macos.sh 验收），后者收编发版速查（纯
vX.Y.Z tag、三资产、--clobber）与既有约定（changelog 分主题、auth-key 不入库、
45678 开发端口、worktree 预检）。README 用一节短文指向 desktop/README.md 锚点
与 AGENTS.md，不复制细节避免两处漂移。

### 涉及文件

- `AGENTS.md`
- `README.md`
- `.gitignore`
