## feat(聊天): 分生活/工作两种模式，工作模式可开多条会话（`d282e86e3f58`）

- Commit: `d282e86e3f588bc1f18a30571ac42cbbc7e4ec7b`
- 时间: `2026-11-05T11:54:06+08:00`

### 变更内容

侧栏顶部多了一档「生活 / 工作」开关，默认生活。生活模式就是原来的样子：唯一一条主会话（key `web`），网页、终端、钉钉、飞书都接在这条对话上，日常提醒、待办、闲聊攒在同一份上下文里。工作模式下聊天页左侧出现一条会话栏，可以新建、切换、改名、删除多条独立会话，每条各自一份上下文；侧栏的「工作区」（把活交给 codex 这类外部智能体）也收进工作模式，生活模式下这一项不再出现在导航里。

会话名默认取这条会话第一句提问的首行，双击可改名，把名字清空就回到自动取名；主会话不进会话栏（它在生活模式那侧），心跳/计划/目标那些后台会话也不进，只在「设置 → 会话管理」里看得见并能按条清上下文——那张表现在多了「名字」和「归属」两列。工作模式下一条会话都没有时，页面明说「工作模式还没有会话」并给一个新建入口，不拿主会话顶上，也不凭空造一条空会话摆着。

三条纪律：小五正在回复时不切模式也不切会话（开关与列表都会先说明原因）；草稿不跟着换会话跑，写给这条会话的半截话换一条就清；主会话删不掉，要清内容走「清除上下文」。选中的会话与当前模式都只存本地偏好（`friday-chat-session`、`friday-mode`），不写进 config.yaml。

本条同时包含 `scripts/p0_smoke.py` 的登录态修复：它还在发 cookie，而本项目早已改成 `Authorization: Bearer`，整条 P0 在「setup did not create session」这一步就红。现在从 `/api/setup`、`/api/login` 的响应体取 token 并随请求带上，同时新增第 9 项 `chat-sessions` 检查。

### 修改原因

日常对话和"干活"的长对话挤在同一份上下文里：周报聊到第三十轮，提醒喝水的上下文也被同一堆内容占着，压缩与成本都跟着涨。外部智能体那边早就有「工作区 → 会话」两级，但和聊天是两个并列入口，用户得自己记住哪边才是干活的地方。把"这次要几条上下文"变成一档明确的选择，聊天页的会话模型和侧栏的入口都跟着这档走，两边共用同一个前提。

### 实现方式

后端新增工作会话登记 `internal/web/sessions.go`：`work-sessions.json`（数据目录，与 `paused-turns.json` 同级）按可读明文 key 存名字与创建时刻，消息历史本体仍在 `session.json`——框架的 `Session` 结构没有放元数据的位置，另存一份比改别人的存储格式干净。清理跟着会话走：删除时表项、历史（含归档区）与这条会话的调用轨迹、暂停现场一起带走；进行中的会话拒绝删除并提示先停止。不设条数上限，也不做启动 GC：表里有、池里没有的条目是"建了还没说话"的正常状态，会话数就是用户建的数量。文件损坏时保留原文件、放弃加载，不用空表覆盖用户起过的名字。

`/api/sessions` 从只读列表扩成 列表/新建/改名/删除，列表一次回带三类归属（`life`/`work`/`internal`），主会话恒在最前、工作会话按最近活动倒序、后台会话垫底；没活跃过的工作会话把 `updatedAt` 回落到创建时刻，免得界面拿零值时间算出「24664 个月」。`POST /api/chat` 与 `/api/chat/stop`、`/api/chat/resume` 收可选 `session` 字段：不带就是主会话，带则必须是登记过的 key——发消息不能凭空造会话，未登记的直接 400 并说明下一步。历史、上下文占用与压缩这些接口本来就能按 `session` 查，这次只是把 key 真正用起来。配置层加 `workSessionsFile`（默认 `work-sessions.json`），`web.New` 多收一个路径参数。

前端 `store.mode` 驱动两件事：侧栏导航按模式过滤（`NAV` 每项带 `modes`），聊天页按模式决定单会话还是会话栏。会话栏复用工作区页那套 `.ag-rail`/`.ag-item` 样式与交互，聊天页在 `#view-chat` 上切成网格（会话栏占第一列三行，头/滚动区/输入区落第二列），生活模式没有这条栏时版式与原来完全一致，不额外包一层容器。切换会话与切换模式都走同一条 `applySession`：清消息、清草稿、清附件预览与暂停态，再按新 key 重拉历史与上下文占用。回复进行中不切，靠 `store.chatBusy` 一个标志同时挡住侧栏开关、会话行点击与运行看板跳工作区那条深链。`ago()` 从工作区页提到 `format.js`，两处共用。

## feat(聊天): 工作会话可指定项目目录，目录随请求走不改进程全局（`c89a2300a891`）

- Commit: `c89a2300a89131f78dd51295c18ba396bcf4c77f`
- 时间: `2026-11-05T12:29:21+08:00`

### 变更内容

工作模式新建会话时可以选一个项目目录（也可以不选）。选了，这条会话就在那个目录里干活：首轮交代的项目约定（AGENTS.md 全文 + README.md 摘要）从那儿读，文件工具的相对路径按那儿解析，并且那个目录算一个允许读写范围（在 `file.allowDirs` 之外多出来的一个根）。会话行的小字带上目录名（`还没有内容 · proj-a`），没选目录的会话行与以前一样。目录在建会话时选定、之后不可换——换 = 再建一条，与工作区会话"主目录创建后不可切"是同一条纪律；目录不存在或指到了文件时建会话直接 400 并说明下一步，不会留下一条"目录已失效"的会话。`work-sessions.json` 的条目多一个 `dir` 字段。

新建会话从"点一下就好"改成一张内联表单：名字与项目目录都可留空，目录走共用的目录选择弹窗（逐层点选或粘贴路径回车跳转）。

### 修改原因

上一条提交把"要几条上下文"分成生活/工作两档，但工作模式的会话仍然只在同一个进程目录里干活——`brain.go` 里"未来的工作模式切目录时再调一次 SetProjectDir"那句一直没落地。不落地，多条工作会话就只是几份独立的聊天记录，还不能真的进某个项目做事：项目约定读不到，读写文件也要用户自己去改 `file.allowDirs`。

### 实现方式

目录随请求 ctx 走，不改进程级全局字段：新增 `internal/workdir`（`With` / `From` / `Normalize`），取用侧两处按 ctx 优先、否则回落到原值——`Brain.projectWarmup` 读项目约定，`FileTools.roots` 决定相对路径基准与允许范围（会话目录排在 AllowDirs 前面，符号链接逃逸校验照旧按合并后的根判）。之所以不做成"切会话时改一下全局 projectDir"：心跳、计划、目标与普通聊天并发调同一个 Brain，全局值会让一条会话把别人的工作目录改掉；随 ctx 走则各拿各的。

`exec_command` 不跟着切：命令仍在本次运行的系统临时目录里跑，脚本与中间产物不进项目目录这条既有纪律不因为选了目录就变。计划/目标那些后台运行用自己的会话，也不继承聊天会话选的目录。前端把 `WorkspaceView` 的目录选择弹窗抽成 `DirPickerDialog.vue` 共用（工作区页只剩一个 ref 与同名入口，其余调用点不变），聊天页的新建表单沿用工作区页那套 `ag-form` 样式；后端怎么说错误就怎么显示，表单留着让用户改。

`p0_smoke.py` 的 `chat-sessions` 检查加了一段真实链路：fake 模型只回一个不带目录的 `read_file` 调用，带目录的会话里那个相对文件名能读到项目目录里的文件（回包里的绝对路径就是那个目录），同样的请求打在主会话上读不到；目录不存在时 400 且文案带"重选"，重启后这条会话的目录还在。

## feat(智能体): 新会话沿用这台 agent 上次的能力选择（`3a8450c6553d`）

- Commit: `3a8450c6553d990aa2ce705c76974241bc0b2b29`
- 时间: `2026-11-05T12:52:11+08:00`

### 变更内容

在工作区里新建会话时，把最近一条用过这台 agent、且手动选过能力的会话那份 `capChoices` 抄给新会话，会话一建立就照常重放。模型、思考强度、审批模式这些不用再每条新会话点一遍；创建成功的提示会说清沿用了哪几项（"已创建会话，沿用上次这台智能体的模型、思考强度"），没有可沿用的东西时提示照旧说"正在启动 agent"。

### 修改原因

重放机制本来就有——每条会话自己记一份手动选择，重开 app 或进程被空闲回收后按它把值按回去。但新建会话拿到的是空表，于是出现"同一条会话重开还记得、新建一条又得从头选"。用惯一台 codebuddy 的模型和思考强度的人，每次新开会话都要重选一遍。

### 实现方式

播种点在 `CreateSession`（新增 `Manager.inheritChoices`），不在投影里另存一份"按 agent 的默认值"：那份意图已经存在各会话的 `capChoices` 里，多存一处就多一处会漂移。取哪一条按 `updatedAt` 最新（且 `CapChoices` 非空）的那条，所以"改过配置的那条"自然成为下次的模板；换 agent 不抄——各家词汇表不同，把 codex 的模型 id 播给 codebuddy 只会重放失败。

审批模式有一个例外：工作区定成「只读」时不抄这一项（其余照常）。只读是"这个工作区不改东西"的明确意图，把上次用的「全自动」静默带进新会话等于替用户撤了这道设置；「每次都问」「自动」谈的是打扰程度而不是安全边界，那里沿用手选的档就是用户要的效果。抄来的取值若这版 agent 不再提供，重放时照旧逐项跳过，不会因为一个失效选项把会话建不起来。`Handoff` 同 agent 搬选择的逻辑不变，两条路径结果一致。

## feat(终端): 内置交互式终端（内核 PTY + xterm.js，只服务本机）（`7f731ed1984b`）

- Commit: `7f731ed1984bb1509c7e1e4e7b1c9e285d328ea9`
- 时间: `2026-11-05T13:38:55+08:00`

### 变更内容

工作模式的侧栏多了一项「终端」。点开是一个真的交互式 shell：内核起一条 PTY 跑用户的 `$SHELL`，界面用 xterm.js 渲染，键盘、颜色、光标控制与全屏程序（vim/top/less）都照常。进来就自带一个终端，可以开多个标签（默认上限 4）；关掉标签、退出登录或刷新页面会把那条 shell 的进程组收掉，正在跑的命令被终止——这条写在页面头部提示里。不可用时（配置没开、或者不是本机访问）页面直接说原因，不摆一个点不动的空壳界面。

### 修改原因

`exec_command` 是"报一条命令、拿一段输出"：非交互、看不到实时输出、应付不了需要输入的程序，也不适合人自己进去敲两下。这种能力用审批链路做不出来，只能给一个真终端。

### 实现方式

`internal/terminal` 管 PTY 会话与生命周期（Start/Write/Resize/Output/Done/Close、并发上限、退出时 CloseAll）。Unix 用 creack/pty（新增依赖，已 vendor）；Windows 明确报"ConPTY 还没做"，不退化成无 PTY 的管道——那样 vim/top 跑不了、提示符与颜色也没有，看着像坏了。收尾按进程组发 SIGTERM、一秒内没退再 SIGKILL，只杀 shell 会留下它起的子进程挂在已关的 PTY 上。

`internal/admin/terminal.go` 把一条 WebSocket 接到一个会话：文本帧是 JSON 控制消息（客户端 start/input/resize/close，服务端 ready/error/exit），终端输出走二进制帧原样搬运（不做 base64，也省得控制字符被 JSON 改写一遍）。输出通道写不过去就自然回压给 PTY，跟真实终端一样，不丢字节。第一帧必须是 start 并带界面量到的尺寸，否则 shell 按 80x24 排版、回看历史会错位；窗口变化再发 resize。

安全边界两条硬规则：只接受本机回环的连接（`localRequest` 从首次设置那套判断里抽出来共用，配置关不掉这条；`admin.host` 配成 0.0.0.0 的远程/Docker 部署里这个入口直接不可用），以及沿用登录态——浏览器的 WebSocket 加不了请求头，所以 token 走 `?token=`，复用现成的 wrapMedia。人在终端里敲的命令不经过 `exec_command` 的白名单/黑名单/审批卡片，这是"内置终端"的定义而不是实现能补的，文档里明说。

配置在 config.yaml 的 `terminal` 段（enabled 默认开、maxSessions 默认 4、shell 留空按 $SHELL → zsh → bash → sh），这版没有设置页开关。`GET /api/terminal` 报 enabled/local/active/maxSessions，前端据此决定是建连接还是显示原因。前端 `TerminalView` 把 xterm/WebSocket/ResizeObserver 实例放在响应式之外（类实例被 reactive 包一层代理后行为会变），列表里只留渲染要用的字段；侧栏切走时组件不常驻卸载（App 里 v-show），连接与终端照常活着，切回来只重量一次尺寸。代价：内联的单文件页面从约 640KB 涨到约 986KB（gzip 约 291KB）。

## feat(智能体): 工作区新建会话可选内置 Friday（进程内 ACP 适配器）（`02ca7fe6d880`）

- Commit: `02ca7fe6d88031dfc5486ad97c9ee1de98384e06`
- 时间: `2026-11-05T17:08:34+08:00`

### 变更内容

工作模式 → 工作区 → 新建会话，智能体下拉里除了 codex/opencode 这些外部工具，现在第一台就是 `friday（内置）`。选它不需要装任何东西、不涉及登录，一轮对话直接交给内置小五的大脑，但跑在这条工作区会话里：主目录就是会话的 cwd，改动照样轮前快照、逐文件 diff、一键还原，时间线、附件、停止、交接、验证命令、项目记忆这些外围能力与普通工作区会话一模一样。一台外部 agent 都没配的用户，现在也能直接在工作区里开工。

内置那条与外部 agent 的差别在界面上写清楚，不靠用户自己踩：选中它时表单里多一句「用设置里的全局模型与权限，没有会话级模型与审批档位，工作区档位不下发」；创建后的提示不再说"就绪后即可切模型"；会话头部标成 `friday（内置，模型与权限走全局设置）`；「设置 → 智能体」里它不进那份可编辑清单（清单上方一句说明它从哪儿来），保存也不会把它写进 config.yaml。默认选中的仍是用户自己配的那台外部 agent，内置那条排最前但不抢默认位；工作区的默认目录预填也照旧取外部 agent 配的那份。

### 修改原因

工作区是"把活交给别人干"的地方，可内置大脑本来就能读文件、改文件、跑命令，用户想在一个目录里干活时不该被逼着先装一台 ACP agent。反过来，把内置会话另做成一套系统也不行：快照、还原、投影、审批、交接这些能力都在 ACP 编排里，两套并行必然漂移。让内置 Friday 自己成为一台符合协议的 agent，是同时满足"开箱能用"和"只有一套会话模型"的做法。

### 实现方式

不 exec 子进程：`internal/acp/builtin.go` 用两条 `io.Pipe` 顶替 stdin/stdout，一端接既有的 `bridge + NewClientSideConnection`（与外部 agent 完全同样的构造），另一端接 `acp.NewAgentSideConnection(builtinAgent, …)`。`agentProc` 只多了一个 `builtin` 标记，Manager 的协议逻辑零改动；`Manager.ctor(cfg)` 按 `cfg.Builtin` 选构造方式（测试可分别替换）。

条目来源是 `config.AcpConfig.Normalized()` 注入（排最前、`Builtin: true`），`UpdateAcp` 写回前 `WithoutBuiltin()` 剔除，同名配置条目存在时不注入——config.yaml 里每一条都该是"要拉起的外部进程"。配套把 `List/Get/Reload` 的 agent 查找统一改成按归一化清单：不改的话内置会话会被显示成「agent 已删除」，并且每次保存配置都会把它的连接当成失联进程回收掉（这条有守护用例）。

## fix(终端): 终端子 shell 落到 C 字符集时自动补 UTF-8 locale（`89bfc725003e`）

- Commit: `89bfc725003e886ad54bd183713edb648f1c1e16`
- 时间: `2026-11-05T19:13:51+08:00`

### 变更内容

内核起的终端子进程在继承环境缺 LANG/LC_* 或不是 UTF-8 时（GUI 外壳起内核的常见情形），启动前自动补成 UTF-8：继承的已是 UTF-8 就原样不动；否则按 LC_ALL>LC_CTYPE>LANG 找出当前生效值，先按「同语言+.UTF-8」再按 C.UTF-8/en_US.UTF-8/zh_CN.UTF-8 候选挑一个 locale -a 里真实存在的写回 LANG 与 LC_ALL，并留一条日志说明用了哪个。

### 修改原因

### 实现方式

Start 时 effectiveLocale 按 libc 优先级找生效字符集，非 UTF-8 才动手：清掉 LANG/LC_ALL/LC_CTYPE 三个变量后同时写回 LANG（给按规范读的程序）与 LC_ALL（兜住 LC_* 分项），候选经 locale -a 校验且只查一次缓存；只动字符集，TERM 与其余环境照搬内核进程。

## fix(智能体): 会话记录截断保住 rune 边界，问答卡编号超 26 回退数字（`45ddc987d822`）

- Commit: `45ddc987d822c0c2f30fff7dcdc27e389d948a25`
- 时间: `2026-11-05T19:33:05+08:00`

### 变更内容

会话记录文件超 200KB 的字节截断先回退到完整 UTF-8 字符边界再落盘，并把「已达上限」提示改到裁剪之后追加；问答卡通知正文的选项编号超过 26 个时从字母回退成数字。

### 修改原因

裸字节切片会在多字节字符中间切开，文件尾部出现非法 UTF-8；而上一道按 rune 的截断提示（120000 rune 的中文约合 360KB 字节）恰好落在这次裁剪区间里，提示自己会先被切没。选项编号用 rune('a'+j) 加到 26 以外会溢出成 {、| 这类符号。

### 实现方式

writeSessionRecord 在字节截断后用 utf8.ValidString 回退最多 3 字节到 rune 起点，再追加自己的截断说明；questionDetail 的 mark 超 26 时改用 fmt.Sprintf("%d", j+1)。

- `internal/acp/question.go`
- `internal/acp/session_record.go`
