### 变更内容

落地 docs/ACP-AGENTS-P1.md（2026-10-17 改写版）的一期：侧栏新增「智能体」页，每个对话（thread）
创建时绑定一个外部 ACP agent 与一个真实工作目录（之后不可切换），agent 用它自己的工具在该目录
干活；进程空闲 10 分钟回收、重开经 session/load 重接上下文，恢复不可靠走「上下文已重置」降级；
request_permission 强制入队网页审批卡（30 分钟无人处理自动拒绝）；发图、用量记账（acp:<agent>
维度）、设置页 agent 管理与握手诊断一并交付。

### 修改原因

2026-10-17 拍板把 ACP 一期从「派活作业模型」改向「独立对话空间」（7 项边界经用户逐条确认，
见 docs/ACP-AGENTS-P1.md §二）：Zed 的 agent panel 证明 session/load 是生态正规玩法，
对话空间能绕开作业模型的门面/token 未实测风险，把用户可感知价值提前。

### 实现方式

internal/acp 新包四件：proc.go（Setpgid 进程组击杀 N1、握手独立 10s 超时 C7、stderr 脱敏落盘 N5、
不做崩溃自动重启）；bridge.go（实现 acp.Client 9 稳定方法，SessionUpdate 只入队守 C6 红线，
RequestPermission 借 SDK 每请求独立 goroutine 的分发模型阻塞等审批——与门面两拍审批 C1/C2 的
本质差异在 docs/ACP-AGENTS.md §5.1 补了衔接说明）；aggregate.go（文本/思考 ≥1200 字或 ≥3s flush，
tool_call 只取 kind+title 不取 locations C11，工具标题按 toolCallId 跨 update 记忆，25KB
available_commands_update 丢弃）；manager.go（thread 投影落盘 acp-threads.json、重启 running 转
interrupted、每 thread 一进程一连接一串行锁满足 C3、并发信号量按 maxConcurrent、空闲定时回收、
ensureSession 先 session/load 后降级 session/new 并入 note 标注）。internal/approval 增
RequestAlways（respectMode=false 强制入队，30 分钟自定义超时；修正过一版把 remember 当 allow
的返回语义错误，fake agent 测试抓住）。internal/config 增 acp 段（Normalized 默认值、Validate、
yaml.Node 写盘保注释——布尔值须打 !!bool 标签否则回读炸，runtime 快照深拷贝与 Apply 发布）。
internal/admin/acp.go 九条路由，SSE 帧协议与 /api/chat 同形（另有 status 生命周期占位帧），
审批列表复用 /api/approvals 故前端审批卡零改动。前端按拍板 D4 抽共享：blocks.js（块构造/推进
纯函数）+ TimelineBlocks.vue（思考/工具/正文渲染），ChatView 改用共享件、16 个测试文件全过零
行为变化；新增 AgentView.vue（thread 列表状态点、二次确认删除、新建表单预填 agent 默认目录、
SSE 消费同聊天页、status 帧显示在输入中气泡、发图复用 /api/upload 链路）、侧栏「智能体」入口、
设置 → 智能体节（全局参数 + agent 行卡片 + 行内测试 + 保存热生效）。测试用进程内 fake agent
（os.Pipe + JSON-RPC goroutine，prompt 脚本独立 goroutine 防取消信号死锁）覆盖 11 场景，
-race 绿；真机 resume 保真度实测（P1-A 尾项）仍待 opencode/codex-acp 各跑一轮。
