## feat(智能体): 打通 CodeBuddy 与 MiniMax 的提问通道，问答卡支持多选与自由文本（`345cf713a797`）

- Commit: `345cf713a797ec70703a01681a8be97a1d5bf6de`
- 时间: `2026-11-06T11:32:06+08:00`

### 变更内容

CodeBuddy 与 MiniMax 的提问以前都问不到用户：CodeBuddy 在 ACP 模式下先发一条工具授权（选项只有 allow/allow_always/reject）再发一条 interruption，真正的问题在后一条里，Friday 只看到前者，于是卡上写着"未知操作"；MiniMax 走 elicitation 表单，这条通道此前根本没接，agent 只能退化成一条窄权限请求，问答卡显示"在等你回答（0 个问题）"。现在这两家都能正常问、能正常答：CodeBuddy 的提问工具授权自动放行（它不执行命令），问题本身由 interruption 呈现；MiniMax 的表单直接翻译成问答卡。

问答卡同时长出两种新答法：多选（勾若干项一次提交）与自由文本（选项下方多一个输入框，可以直接写自定义答案，对应 CodeBuddy 的 AskUserQuestion 与 MiniMax 的 Other 字段）。没答（超时或本轮结束撤卡）回 cancelled/deny，不替用户挑一条；多选卡目前仍是一次点一条（卡上会有提示）。权限请求缺 title 时（CodeBuddy 的 ACP 权限请求常见），摘要按 `_meta` 里的工具名与 rawInput 的关键字段（命令/文件/URL/查询）兜底，不再统一显示"未知操作"。

### 修改原因

问答卡这条链路是按 zcode 的一家协议写的：zcode 把答案编码进权限请求的选项，Friday 按选项画按钮就成立。换了 agent 就不成立——CodeBuddy 的问题压根不在权限请求里，MiniMax 用的是另一条协议方法。这两家都是用户实际在用的 agent，提问问不到人，agent 就会自己替用户做决定，或者卡住等一个永远不来的答复。

### 实现方式

新增 `internal/acp/interactions.go` 承接两类"提问不走 request_permission"的 agent：`clientCapabilitiesFor` 按 agent 白名单声明交互能力（CodeBuddy 的 `_meta["codebuddy.ai"].question`、MiniMax 的 `elicitation.form`），只对实测过的通道开口，不把实验能力广播给所有 agent（会改变它们的工具暴露面）；CodeBuddy 的 `_codebuddy.ai/question` 扩展方法与 MiniMax 的 elicitation 表单各自翻译成"问题 → 卡片 → 答复"，两条路都阻塞等用户作答，SDK 已把入站请求放在独立 goroutine，直接复用审批队列的问答卡。CodeBuddy 的 interruption 走 `session_info_update` 的 `_meta`，异步出卡后回 resolveInterruption——这类消息不能交给时间线聚合器丢掉。

新增 `internal/acp/permission.go` 把权限请求翻成人人话：摘要按 title → meta 描述 → rawInput 关键字段 → 工具名 → kind 的顺序兜底，任何一条能读出信息就不该出现"未知"。`internal/approval` 的问答卡加 `AllowText`/`TextPlaceholder`/`MultiSelect` 三个字段与 `DecideText`/`DecideOptions` 两个结算口，文字答案上限 4000 字（按 rune 计，防误粘贴整篇文档）；`internal/admin/ext.go` 的审批端点相应识别 `choices` 与 `text`。

`internal/acp/question.go` 补 MiniMax 退化问卷的识别：选项 id 带 `questionnaire:<请求id>:` 前缀、题干在 toolCall.title 里，不补这一条，卡片会显示"0 个问题"。vendor 侧给 `UnstableCreateElicitationForm`/`UnstableCreateElicitationUrl` 打了一处本地补丁，补上 sessionId（MiniMax ACP 实测要带，上游稳定类型尚未收录；注释已写明上游收录后整体移除）。

验证：`internal/acp/manager_test.go` 新增 7 条守护用例（扩展方法提问、elicitation 表单、interruption 提问、interruption 文字答、elicitation Other 文字答、interruption 多选、elicitation 多选）；`internal/approval/approval_test.go` 3 条（文字答只给问答卡、多选只给多选卡）；`internal/admin/manage_test.go` 2 条 HTTP 用例（text 与 choices 端到端）；`web/tests/approval-cards.test.js` 4 条前端用例（多选勾选与回传、没勾选时提交置灰、不声明时无输入框、允许时走 text）。

## feat(终端): 工作区对话右侧内嵌终端面板（`24e6e6a43a87`）

- Commit: `24e6e6a43a875f6cd4c2470466f7761cf955b5e6`
- 时间: `2026-11-06T11:32:18+08:00`

### 变更内容

工作区对话页的会话头部（文件、全屏按钮旁）多了一个终端按钮。点开后对话分成两栏：左边是原来的对话（头部、提示条、消息流、输入框），右边是终端面板。面板里能开多个终端标签，新开的终端直接落在当前会话的主目录（= 工作区主文件夹）。收起面板不打断终端——连接、缓冲与屏幕内容都保留，再点开原样回来；只有退出登录或重启软件才收掉（关掉某个标签仍会终止那条 shell，和侧栏那页同一语义）。它与侧栏「终端」页共用同一套内核通道与上限，两边一起算 `maxSessions`。

终端的滚动回滚上限写死在代码里（8000 行），超过就把最上面的输出顶掉——日常终端就是这么做的，不暴露成设置项。

### 修改原因

侧栏「终端」页是另一个页面，想看终端就得切走，正在跟 agent 对的话就断了；agent 让它跑个命令、看一下结果，用户得在两个页面之间来回切，回切后对话现场还得重新找。内嵌到工作区对话旁边，终端和对话同屏。

### 实现方式

新增 `web/src/components/WorkspaceTerminal.vue`，与 `TerminalView`（侧栏终端页）同一套内核协议（一条 WebSocket 一个真 PTY），三处刻意不一样：

1. 面板收起用 `v-show` 而非卸载，组件不销毁——WebSocket 与 xterm 实例都还活着，输出照常进缓冲，重新展开内容原样都在；只有卸载（登出、会话被删）或重启软件才收掉。
2. 起始目录由父组件传（`cwd = current.cwd`，会话主目录 = 工作区主文件夹），开 tab 那一刻取值，之后换会话不影响已开的终端。
3. 回滚行数写死为组件内的 `SCROLLBACK = 8000` 常量，注释即文档，不做成设置。

`WorkspaceView.vue` 的会话头部加终端按钮（有按下态表示面板开着），对话区整体收进 `.ag-chat`，右侧 `.ag-split` 放终端面板；`style.css` 补 `.ag-split` / `.ag-chat` / `.wt-*` 面板样式（面板宽 `min(46%, 620px)`，最小 300px，标签条复用终端页的 `.term-tab` 族）。xterm / WebSocket / ResizeObserver 实例一律放在响应式之外（普通 Map），类实例被 reactive 包一层代理后行为会变。

验证：新增 `web/tests/workspace-terminal.test.js` 10 个用例（start 帧带 cwd、收起/展开连接不断、收起期间输出照进缓冲、回滚上限、关标签协议、不可用态、卸载收尾等）；`npm run check` 全过（463 用例），`vite build` 通过。

## feat(终端): 终端面板跟着会话走，对话/终端分栏支持拖拽调宽

### 变更内容

内嵌终端面板从"全局只有一个"改为"每条会话一个"：开合状态与面板实例都挂在会话上，切到没开过终端的会话，面板不会自动出现；切回开过的会话，面板与里面的终端标签原样回来（连接、缓冲、内容都保留，不重开连接）。面板收起仍是 v-show 常驻，卸载时机不变（登出、会话被删、重启软件）。

对话与终端之间加了可拖拽的分隔线：左右拖动调整两栏比例，钳在 30%–70%（对话最多占 70%，终端最多也占 70%），比例全局记忆——换会话不重置。拖动中锁定 col-resize 并禁文本选中，xterm 靠 ResizeObserver 跟着重排。

### 修改原因

面板开关原本是一个全局布尔：A 会话开了终端，切到 B 会话面板还开着，而 B 从没要用终端；更糟的是两栏里摆的还是那条 A 会话的终端，"终端落在会话主目录"名不副实。分栏宽度原先写死 `min(46%, 620px)`，宽屏想多看对话、窄屏想让终端占大头都做不到。

### 实现方式

`WorkspaceView.vue` 的会话级缓冲（`states`）补 `termOpen` / `termMounted` 两个字段：终端按钮切换当前会话的 `termOpen`，第一次打开才把该会话的 `WorkspaceTerminal` 实例挂上（`v-if` + `v-show` 组合），之后收起/切走都只是 `v-show`；实例的 `cwd` 用各自会话的主目录，标签在开的那一刻定格。分隔线是 `.ag-split` 里一个 9px 宽（负 margin 挤进边界、实际占位 1px）的竖条，pointer 事件拖动更新 `termW`（0.3–0.7 钳制），面板宽度经内联样式下发，CSS 保留 `min-width: 300px` 兜底窄窗口。

验证：`web/tests/workspace-view.test.js` 新增 3 条用例（没开过的会话不自动开、切回原样在不重挂；每条会话各开各的终端、start 帧 cwd 各自定格；拖拽钳制 30%–70% 且松手不再跟随）；`web/tests/workspace-view.test.js` + `workspace-terminal.test.js` 共 83 条全过，`web` 全量 466 条通过。
