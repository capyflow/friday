### 变更内容

internal/task 任务引擎的调度内核由自研 time.Timer + robfig/cron 组合改为复用 vortexagent/autonomous 的 Scheduler 与触发器（OneShot/Interval/Cron），Engine 本身只保留 Task↔Goal 映射、唤醒循环、到期分发与 JSON 持久化薄层；store.go 仅同步注释。

### 修改原因

### 实现方式

## fix: MCP 子进程生命周期绑定 context 并加固启动参数校验（`4b7cad54920e`）

- Commit: `4b7cad54920e27cb509ca84aafee706c021f31b7`
- 时间: `2026-09-25T00:28:30+08:00`

### 变更内容

internal/mcp 客户端启动 MCP 服务器子进程改用 exec.CommandContext 绑定 Client 私有 context，Close 时取消即终止子进程并保留 Kill 兜底；启动前显式校验命令非空、命令与参数不含控制字符（\x00\r\n）并经 exec.LookPath 解析可执行文件，管道创建/启动失败的各出口补调 cancel。

### 修改原因

此前子进程生命周期仅依赖 Close 时的显式 Kill，未与生命周期 context 绑定；且无效启动命令要到启动阶段才报出模糊错误。绑定 context 与前置校验让异常退出更可靠、配置错误尽早有明确报错；命令来源仍限定为 config.yaml 管理员可信配置，不经 shell、不接外部输入。

### 实现方式

Start 内 context.WithCancel(context.Background()) 建私有生命周期，cmd.CommandContext 挂接；每个失败返回路径调用 cancel 防泄漏；Close 幂等序调整为 cancel → Kill → 关 stdin；参数逐项 ContainsAny 检查控制字符，LookPath 失败直接返回带服务器名的明确错误。

- `internal/mcp/client.go`
