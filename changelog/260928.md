# 260928 · 记忆系统 wiki 化 + 管理后台 Wiki 浏览/编辑

## 主题：记忆引擎升级（扁平列表 → wiki 页面仓库）

### 背景
原长期记忆是扁平 JSON 列表（一条一句话事实，关键词子串检索，靠 `replaceId` 手动覆盖矛盾）。
本次按"LLM wiki"形态重构：记忆按主题组织为页面，整编（合并/去重/矛盾改写）由 agent
在对话中自维护完成（先查相关页 → 合并正文 → 整体保存），管理后台提供 wiki 文档式浏览与编辑。

### 存储层（internal/memory）
- `Store`（扁平 JSON 列表）重写为 `WikiStore`：每页一个 `<id>.md` 文件
  （YAML frontmatter：id/title/source/created/updated + markdown 正文），
  tmp + rename 原子落盘，重启恢复；损坏页面跳过不崩溃。
- API：`Save`（id 非空按 id 更新；id 空按标题 upsert，返回 created）、`Read`、
  `Delete`（容忍 `#` 前缀）、`Pages`/`Search`（标题+正文子串匹配，正文命中附 UTF-8
  安全片段）、`Count`。页面 ID 校验字符集，防路径穿越。
- 一次性迁移：wiki 目录为空且旧 `memories.json` 存在时，全部旧条目按时间顺序
  迁入《用户档案》页（source=migrate），旧文件保留不删。

### 工具层（internal/tools/memory.go）
- `remember`：改为 `title + body`（body 为合并后的完整正文，整体替换保存），
  可选 `id` 指定更新页；移除 `replaceId`（页内合并已覆盖其语义）。
- `recall`：两步用法——`q` 搜索返回页面列表+命中片段，`id` 读整页正文；空参返回全部页面。
- `forget`：整页删除；描述中明确"部分过时用 remember 改写、整页过时才 forget"。
- 工具名保持不变，系统提示词改动最小。

### Agent（internal/agent）
- `Deps.Memory` 类型改为 `*memory.WikiStore`。
- 系统提示词【长期记忆】重写为 wiki 工作流：按主题分页、先查再合并、矛盾改写、
  整页过时才删除、克制记录。

### 管理后台（internal/admin + cmd/robot/main.go）
- 新 API 替换原 `/api/memories` 三端点：
  `GET/POST /api/wiki/pages`、`GET/PUT/DELETE /api/wiki/pages/:id`（wrap 鉴权不变）。
- 状态页记忆计数改为页面数；Info.MemoryFile → MemoryDir。
- 前端"记忆"视图重做：左侧页面目录（搜索 + 更新时间/来源 + 片段预览），右侧
  `renderMD()`（内联 marked.js，XSS 转义与链接白名单）渲染正文，支持新建/编辑
  （原始 markdown textarea）/删除；样式复用聊天气泡 `.md` 排版规则扩展 `.wiki-body`。

### 配置
- `memory.dir`（默认 `memories`）为 wiki 页面目录；`memory.file` 保留作迁移来源。
- `config.yaml.example` 同步更新。

### 测试
- `internal/memory`：新建/更新/校验（含路径穿越 ID 拒绝）、删除（# 前缀）、
  落盘往返、损坏页面容错、旧记忆迁移（含只迁一次、损坏跳过）。
- `internal/tools`：remember/recall/forget wiki 链路、同标题合并写入、缺参报错。
- `go build ./... && go vet ./... && go test ./...` 全绿；前端应用 JS 经 node --check 语法校验。

### 明确不做（本期）
- 本地 embedding 语义检索（vortexagent Provider 无 embedding 接口，ROADMAP P2）。
- 周期后台自动整编任务、页面版本历史、RAG 知识库。

## 主题：桌面端落地（Tauri v2 外壳 + Go sidecar + 打包脚本）

### 桌面外壳工程（desktop/，新增）
- `src-tauri/src/main.rs`（~220 行，无业务）：sidecar 拉起内核（`--desktop --data-dir <系统配置目录>/Friday --port 0`）、
  数据目录首启播种 config.yaml（对齐 docker entrypoint 模式）、解析 `friday.env`（KEY=VALUE）注入子进程环境
  （解决 Finder/Dock 启动无 shell 环境变量）、解析 stdout `FRIDAY_ADDR=` 导航主窗口、
  内核 Terminate → 错误页、`Alt+Space` 全局快捷键创建/切换 /palette 透明弹窗（失焦隐藏不销毁）、
  退出时 stdin 写 `/quit` 3s 后 kill 兜底；single-instance 防多开。
- 零 JS 构建链：`withGlobalTauri` 全局 API，无 npm 工程；`ui/` 为启动占位页与内核错误页。
- `scripts/gen-icon.py`：纯 stdlib 画 PNG 产出全套图标（32/128/256 png + icns + ico + 1024 底图），
  无需设计资源与网络。

### Go 侧契约补齐（cmd/robot/main.go、internal/admin）
- 补齐半成品 helper：`freePort`（--port 0）、`waitReady`（轮询 GET / 至 200）；
  桌面模式服务就绪后 stdout 打印 `FRIDAY_ADDR=http://127.0.0.1:<port>`（stdout 仅此一行，日志走 stderr）。
- 桌面模式退出链：无终端 REPL；stdin `/quit` 或 EOF → 统一优雅退出；ppid=1 看门狗（30s）兜底孤儿进程。
- 管理后台新增 `GET /palette` 弹窗页（go:embed + 公有静态路由，模式同 handleIndex）：
  Spotlight 风格输入框，同源 POST /api/chat SSE 流式渲染；未登录提示先去主窗口登录；
  Esc 经 __TAURI__ hide 窗口（浏览器直访降级关标签）。

### 打包脚本（desktop/scripts/build-release.sh，最终交付物）
- 一条命令：图标 → `CGO_ENABLED=0 go build -trimpath -ldflags "-X main.version=<ver>"` 出
  `binaries/friday-<target-triple>` → 拷贝 config.yaml.example 到 resources → `npx tauri build` 出
  dmg/nsis/deb/AppImage → 列产物清单。
- 参数：`--debug`、`--version`（同步注入 Go 与 tauri.conf 版本）、`--sidecar-only`（配合 tauri dev）、
  `--skip-icon`/`--force-icon`、`--bundles`（缺省按系统 mac=dmg/linux=deb,appimage/win=nsis）。
- 桌面端构建产物（target/binaries/resources/icons/gen）加入 .gitignore；desktop/README.md 为操作手册。

### 桌面端首跑修复（真机反馈）
- 数据目录路径修正：`app_config_dir()` 在 Tauri v2 已含 identifier（com.capyflow.friday），
  再 join "Friday" 产生嵌套目录；改用 `config_dir()` + "Friday"，与内核 `--desktop` 缺省
  及文档一致（`~/Library/Application Support/Friday`）。
- 内核可观测性：外壳捕获 sidecar 双流输出，持续追加数据目录 `friday-kernel.log`；
  内核异常退出时取最后一条 stderr 作为死因经 query 带入错误页展示
  （首跑最常见死因：Finder 启动无环境变量 → `DEEPSEEK_API_KEY 未设置`，此前用户不可见）。
- 错误页重写：展示真实死因 + 数据目录路径 + friday.env 配置指引。
- sidecar cwd 修正：allspark-go/logx 在包 init 阶段（早于 Go 侧 chdir）mkdir ./logs，
  launchd 拉起的进程 cwd=/（只读）直接 panic；外壳拉起内核时显式 current_dir=数据目录。
  该 panic 此前不可见，本次新加的 friday-kernel.log 首次捕获。

### API Key 体验重构（真机反馈）
- 通用命名：密钥环境变量默认 `FRIDAY_API_KEY`（不再绑定 DeepSeek）；解析链
  provider.apiKey 直填 → apiKeyEnv 指定变量 → FRIDAY_API_KEY → 旧名 DEEPSEEK_API_KEY（兼容）。
- 未配置密钥不影响打开软件：Validate 移除密钥强校验，Build 允许空密钥建 Agent
  （LLM 请求在补配前报错指引）；启动时日志提示，管理后台状态卡显示"未配密钥"。
- 软件内配置密钥：管理后台「设置」页新增 API 密钥输入框（密码态，不回显），
  经 /api/provider 热生效并写回 config.yaml 的 provider.apiKey（yaml.Node 保留注释）；
  /api/status 返回 apiKeyConfigured 驱动输入框占位提示。桌面端种子配置/错误页/README
  同步改为推荐软件内配置，friday.env 改用 FRIDAY_API_KEY 通用名。

### 占位页竞态修复 + 应用图标抛光（真机反馈）
- 竞态修复：内核就绪事件可能早于占位页 JS 注册监听（首启 webview 加载慢时），
  事件丢失 → 永远卡在"正在启动本地内核"。新增 kernel_state 查询命令（addr/dead/reason
  快照），占位页改为"启动先查一次 + 事件 + 1.5s 轮询"三重保障；30s 无进展给出
  排障提示；死因同样经查询兜底。
- 图标：对角渐变（靛蓝→紫红）、气泡/圆点加大，重新生成全套（icns/ico/png）。
- 应用图标重设计：白色机器人脸（竖椭圆眼/微笑/天线/耳罩）+ 三段对角渐变底 +
  顶部光泽 + 高斯柔影，纯 stdlib 绘制；全套（icns/ico/png/1024 底图）重新生成。
- 安装后"没有图标"根因修复：手写 icns 结构 sips 能读但 iconutil/系统图标服务不认。
  gen-icon.py 改为只绘制底图（app-icon.png）与常用 PNG，icns/ico 容器统一由
  `npx @tauri-apps/cli icon` 官方工具生成（build-release.sh 图标步骤接入），
  iconutil 验证全尺寸可解析。
