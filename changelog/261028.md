## feat: 子进程平台差异收进 internal/procctl，Windows 适配（`bada2b48`）

- Commit: `bada2b480b60c8c9bb1ca8f468335dbd8a7c5971`
- 时间: `2026-10-28T01:09:09+08:00`

### 变更内容

新增 internal/procctl 平台分叉包（procctl_unix.go / procctl_windows.go / shell_windows.go），
统一子进程的平台纪律：Prepare（Start 前）/ Attach（Start 后挂整树击杀载体）/ ShellCommandContext
（跑一条 shell 命令行）。ACP agent（proc.go）、ACP 安装命令（catalog.go runInstallCommand）、
MCP 服务器子进程（mcp/client.go）与桌面 PATH 补齐（cmd/robot/path.go）接线。Windows 从此可编译：
此前 internal/acp 直接用 Setpgid/syscall.Kill（Unix 专有），GOOS=windows 全仓编译失败。

### 修改原因

explore/acp-agents 的 ACP 智能体空间只在 mac/linux 验证过；Windows 的 syscall 包没有
Kill/SIGKILL，SysProcAttr 也没有 Setpgid 字段，编译都过不了。整树击杀（N1：kill 时连
npx→node→agent 自 spawn 的孙进程一起带走）与无黑窗是 Windows 侧的对应语义缺口。

### 实现方式

Windows 侧参考 Zed（crates/util/src/process.rs）同款实现：Job Object 挂
JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE（父进程崩溃内核回收句柄时整树连带终结）+
TerminateJobObject，经 vendor 里已有的 golang.org/x/sys/windows 翻译，零新依赖；spawn 加
CREATE_NO_WINDOW 防 sidecar/GUI 拉起 npx 闪黑窗。Attach 失败（进程瞬亡等罕见情形）退化为
只杀直接子进程——agent 主进程必死、SSE 断开照常，孙进程可能残留，接受（Zed 的 spawn-assign
竞态同款接受）。安装命令的 sh -c 改为平台 shell：Windows 优先 Git Bash（官方目录的安装命令
多为 curl|bash 类 POSIX 语法，PowerShell 跑不了；GIT_INSTALL_ROOT 或顺 PATH 里 git.exe 定位
安装根 bin\bash.exe），找不到退 PowerShell -NoProfile -Command（npm install -g 仍可用）。
CombinedOutput 无法在 Start 与 Wait 之间挂 Job Object，runInstallCommand 改为手工编排输出
收集与 Attach（Cancel 闭包经锁与 Attach 竞态对齐）。Unix 侧行为零变化（Setpgid + 负 pid
killpg 原样平移）。augmentPath 补 Windows 侧用户目录：%APPDATA%\npm（环境变量缺失按布局推）、
~\scoop\shims、~\AppData\Local\pnpm；Homebrew/nvm 等 Unix 目录不再在 Windows 上追加。

### 变更内容

Windows 上首跑全量 go test 的六包失败修复：HOME 隔离补设 USERPROFILE（os.UserHomeDir 在
Windows 读 USERPROFILE 而非 HOME，admin/skill 四处 t.Setenv("HOME") 隔离失效）；0600 权限位

CI 只有 ubuntu job，这些平台假设从未暴露；分支要加 Windows CI 必须先让存量用例在
Windows 上真实通过。

### 实现方式

USERPROFILE 与 HOME 同时设置（互不影响其他平台）；权限位断言包在 `runtime.GOOS != "windows"`
闸里并注明原因；fixture 增加 windows-x86_64 分发条目（registry.go 的 platformKey 本就支持
windows 键，产品侧无需改动——cmd 路径处理经 FromSlash 已跨平台）。

## fix: 闪念时间线 CreatedAt 强制严格递增，排序只比墙钟（`fc27313`）

- Commit: `fc27313292af27359f9f66f6b3d8223d049a6652`
- 时间: `2026-10-28T01:09:21+08:00`

### 变更内容

internal/todo 的 Store 增加 lastCreated，AddEntry 强制 CreatedAt 严格递增（now 不晚于
lastCreated 时取 lastCreated+1ns）；ListEntries 与 List 的排序比较经 Round(0) 只比墙钟。
测试侧把「两批条目间 sleep 2ms」提到 25ms 并注明依据。

### 修改原因

Windows 首跑测试暴露：本机实测同 tick 内两次 time.Now() 读数精确相等（系统时钟粗粒度），
且 sleep 25ms 后读数反而倒退 25ms（NTP 回拨）——「后创建的条目时间更大」这一时间线排序
假设不成立，闪念页时间线顺序退化为不确定。Linux 的纳秒精度时钟掩盖了问题。

### 实现方式

lastCreated 仅在 opMu 串行的写路径更新（AddEntry）；排序处 Round(0) 剥离单调钟——Windows
上单调钟读数同样可能回退，剥离后比较与 lastCreated 的墙钟纪律一致，时间线顺序由入库先后
唯一决定。持久化文件无需迁移：JSON 反序列化的 time.Time 本就只含墙钟。

### 涉及文件

- `internal/todo/todo.go`
- `internal/todo/entry.go`
- `internal/todo/entry_test.go`

## ci: 加 Windows 测试 job 与 GOOS=windows 交叉编译门禁（`3b564fc`）

- Commit: `3b564fcae09d31cf2ec916fc4e36f16efd43db75`
- 时间: `2026-10-28T01:09:29+08:00`

### 变更内容

check.yml 的 ubuntu job 增加一步 `GOOS=windows CGO_ENABLED=0 go build ./...` 交叉编译门禁；
新增 checks-windows job（windows-latest）跑 go test / vet / build。

### 修改原因

本轮全部 Windows 问题的共同根因是 CI 只在 ubuntu 上跑，平台专有调用（syscall.Kill/Setpgid）
与平台假设（HOME、权限位、时钟）静默积累。两道门禁分工：交叉编译挡「平台专有 API 回潮」
（无需 Windows runner 分钟数），Windows job 挡「测试的平台假设回潮」。

### 实现方式

Windows job 不跑 -race（需要 mingw 工具链），竞态门禁由 Linux job 承担；web 测试仍只在
ubuntu 跑（纯 JS，无平台差异）。

### 涉及文件

- `.github/workflows/check.yml`

## 已知边界（本轮不做）

- **ACP 官方目录在 Windows 的安装覆盖面**：curl|bash 类安装脚本经 Git Bash 可跑，但脚本内
  常假定为 Unix 布局（装到 ~/.local/bin 等）；npm install -g 类（codex/claude/gemini/zcode
  适配器）可用。binary 分发条目取决于上游是否提供 windows-x86_64 产物（platformKey 已支持）。
- **npx.cmd 拉起链路未真机实测**：Go exec 直接启动 .cmd 的引号转义规则与 Unix 不同，agent
  首次在 Windows 上跑通全链路仍需验证（桌面端打包 + 首装向导走一遍）。
- **0600 的 ACL 语义**：Windows 上仅声明写盘意图，未做 ACL 收紧（config.yaml 含 API key），
  跟进项。
