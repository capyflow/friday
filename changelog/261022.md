### 变更内容

聊天与智能体时间线正文里输出的本机文件路径（行内代码形态，如 `/Users/xxx/减脂计划.md`）渲染成可点 chip，点开右侧滑出预览抽屉：markdown 按同一管线渲染、代码/文本走 pre、图片内联、二进制给提示；抽屉里再命中的路径可继续点开。新增 `GET /api/files/preview` 只读取回内容。

### 修改原因

模型输出「文件已写好 + 路径」后，用户要自己开编辑器或 Finder 才能看内容，对话流被打断；浏览器拿不到本地文件，必须由后端配合一个只读入口才能在页面里预览。

### 实现方式

后端 files.go：登录后只读，`os.Stat` 限普通文件，magic number 嗅探图片（≤8MB 内联 dataUrl），文本按 NUL 字节判二进制、512KB 截断带标记，扩展名优先给 mime 标签（Go mime 表在部分系统缺 .md）；信任档与 agent 读工具一致（仅本机监听 + 需登录，不做目录白名单）。前端 md.js：renderMD 加 `fileChips` 开关（仅时间线开启，Wiki/闪念不受影响），行内 code 严格启发式识别（`/` 开头、排除站点路由与协议形、末段 1–8 位扩展名），命中转 `button.file-chip` 全程 DOM API 构造无注入面；TimelineBlocks 点击委托出 `preview` 事件，ChatView/AgentView 挂同一个 FilePreviewDrawer。测试：后端 5 例（内容/拒目录/截断/二进制图片/`~` 展开），前端 md.test.js 新增路径识别与 chip 转换用例。
