# 261116 变更记录

## fix(界面): 流式思考预览不再顶出对话列宽

- 时间: `2026-11-16`

### 变更内容

智能体会话页里，过程行（那一行「N 次思考 · M 次工具调用」）在流式期间会把
当前思考的一行预览直接当成标题显示。这一行现在**不再越出对话列宽**：预览
文字被截断在列宽内并以省略号收尾，开合箭头也跟着回到列内。中文预览同样
生效。工具名被截断时，悬停仍能看到完整名字（title 里留了全名）。

### 修改原因

过程行的标题用的是 `.step-name`，而它是 `flex: none`——不许收缩。流式
思考预览一行可达一百多字符（`thinkPreview` 取思考最后一行，最多 120 字），
于是这个标签按内容宽度撑到 750px 左右，比对话列宽（700px）还宽，把开合
箭头一起顶到窗口外面。裸思考行没这个问题：它用 `.think-title`（`flex: 1` +
`min-width: 0` + 省略号），本来就截得住。

### 实现方式

- `web/src/style.css`：`.step-name` 改成 `flex: 0 1 auto`，并补上
  `min-width: 0` + `overflow: hidden` + `text-overflow: ellipsis` +
  `white-space: nowrap`。短标签（次数、工具名）仍是内容宽，箭头照旧贴着
  文字；长标签才收缩省略。外部 agent 的长工具名同样受益。
- `web/src/components/ToolStep.vue`：工具名与展示名加 `title`，被省略号截掉
  时悬停能看全名。
- 测试：`web/tests/timeline-blocks.test.js` 加样式层守卫（`.step-name` 不许
  再写回 `flex: none`，且必须带收缩与省略）。

### 涉及文件

- `web/src/style.css`
- `web/src/components/ToolStep.vue`
- `web/tests/timeline-blocks.test.js`

## fix(智能体): 交互式登录的 agent 收起「立即认证」，认证入口只留终端与凭据

- 时间: `2026-11-16`

### 变更内容

设置 → 智能体 → 认证面板里，登录必须由人完成的 agent（codebuddy、
codebuddy-code）不再渲染「由 agent 自己认证」那一组按钮（iOA / Google-Github /
微信 / 企业域名 四条「立即认证」），只保留「在终端里登录」与「保存凭据」两条。

### 修改原因

那四个按钮走的是 ACP `authenticate`，而 codebuddy CLI 的实现是：**已登录就先
登出再登录**（logout-origin.json 里 reason=acp_reauthenticate），随后开一个浏览器
登录页等授权。后果是：

- 已登录时点一下就把现有登录清掉（人刚在浏览器登好，回来发现又未登录）；
- 每次点击多开一个登录页，还会把进程晾在那里等 120 秒；
- 探测阶段若误调它，会沿着 iOA → 国际站依次开页，一次探测弹 2–3 个登录页。

实测登录本就走 CLI 自己的凭据文件，终端里 `/login` 一步就能完成，这四个按钮
属于「既没用上、又有副作用」的入口，先收起来。

### 实现方式

- `internal/acp/auth.go`：`AuthStatus` 增加 `interactive`（取自 `guide.interactive`），
  面板据此决定渲染哪些认证方式；`codebuddyHint` 去掉「点立即认证」的引导，改成
  走「在终端里登录」+ 站点说明。
- `web/src/components/settings/AcpSection.vue`：新增 `authMethods(status)`，交互式
  agent 过滤掉 `type === 'agent'` 的方式。
- 测试：`auth_test.go` 断言 codebuddy 的状态带 `interactive`；
  `acp-settings.test.js` 断言交互式 agent 面板里没有「立即认证」、仍有终端与凭据入口。

### 涉及文件

- `internal/acp/auth.go`
- `internal/acp/auth_test.go`
- `web/src/components/settings/AcpSection.vue`
- `web/tests/acp-settings.test.js`

## feat(智能体): agent 列表只露登录态，三个操作收进详情页

- 时间: `2026-11-16`

### 变更内容

设置 → 智能体 的清单改成「一行一台」：每行显示名称、版本、停用标记、启动命令
摘要与**登录态徽章**；点这一行弹出该 agent 的详情页，认证 / 测试 / 删除三个
操作与全部可编辑字段（命令、参数、超时、预认证方法、环境变量、逐 agent 工具
白名单）都在详情页里。

### 修改原因

原来每行右侧固定三颗按钮，八台 agent 就是二十四颗按钮，列表被压成按钮墙；
而人最想一眼看到的「这台登录了没」反而不在列表上（要先点「认证」才出徽章）。
另外，之前展开字段是就地折叠，展开后整行高度跳动，滚动位置也跟着乱。

### 实现方式

- 列表徽章走**本地快查**：新增 `Manager.AuthQuickStatus`（只看环境变量、凭据文件、
  配置里的密钥，**不拉起 agent 进程**），接口 `GET /api/acp/auth?agent=X&quick=1`。
  八台各拉一次进程要 2–16 秒，非交互式的 `authenticate` 还会开登录页，列表不该付
  这个代价；判不出来就回 unknown（显示「未检测」），不硬说「未登录」。
  详情页点「认证」才做完整探测。
- 详情页是遮罩弹层（点遮罩或 Esc 关闭），沿用原有的表单与认证面板，只是换了位置。
- 安装完成 / 添加到清单 / 新增 agent 后直接打开那台的详情页。

### 涉及文件

- `internal/acp/auth.go`（`AuthQuickStatus` + `quickLoginState`）
- `internal/admin/acp.go`（`quick=1` 分支）
- `internal/acp/auth_test.go`（快查不拉起进程、凭据命中、unknown 不误判）
- `web/src/components/settings/AcpSection.vue`（列表行 + 详情弹层 + 快查徽章）
- `web/tests/acp-settings.test.js`

## fix(智能体): 补上 minimax / qoder / zcode 的凭据路径，列表徽章不再「状态未知」

- 时间: `2026-11-16`

### 变更内容

`credFiles` 增加三台 agent 的凭据落点，列表徽章的本地快查能直接判出已登录：

| agent | 凭据文件 |
|---|---|
| minimax / minimax-code | `~/.minimax/auth/prod/cn/mcode-public/auth.json` |
| qoder | `~/.qoder/.auth/user` |
| zcode | `~/.zcode/v2/credentials.json`（旧的 `~/.zcode/auth.json` 一并保留） |

### 修改原因

这三台的徽章一直显示「状态未知」，点「认证」又立刻变「已登录」。原因是列表
徽章走本地快查（不拉起进程），而快查只认 `credFiles` 里登记过的路径——这三台
没登记，于是快查一律落到「本地没有可判定的凭据」；「认证」是完整探测（拉起
进程问 agent 自己），所以立刻有结论。补上路径后两者口径一致。

### 涉及文件

- `internal/acp/auth.go`
- `internal/acp/auth_test.go`（三条路径的表驱动用例）

## feat(智能体): 进页面后台逐台问 CLI（safe 探测），徽章不再靠维护路径

- 时间: `2026-11-16`

### 变更内容

设置 → 智能体 打开后分两段出状态：

1. **先本地快查**（`quick=1`，毫秒级、不拉进程）把徽章填上，页面立刻可用；
2. **再后台逐台问 CLI**（新增 `mode=safe`）：拉起 agent、握手、建一次会话，
   结果回来逐个替换徽章。同一台 10 分钟内不重复问，标题行显示「后台核对中 i/n」。

### 修改原因

原来只认 `credFiles` 里登记的凭据路径，没登记的 agent（minimax / qoder / zcode）
徽章永远是「状态未知」，点「认证」又立刻有结论——因为那条路是拉进程问 agent
自己。既然结论只有 CLI 才知道，就该去问 CLI；但不能同步问：八台各 2–16 秒，
页面会卡半分钟以上，而且八台并行会同时拉起八个 node 进程。

### 实现方式

- `AuthStatusSafe`：与 `AuthStatus` 同一套流程，但**绝不调 authenticate**，
  只 initialize + `session/new` 试探。这样对 codebuddy（会先登出）与其它会开
  浏览器的 agent 都无副作用，可以放心当巡检手段。
- 判不出结论时回 `unknown` 并指路「点认证完整检测」，不把「没结论」当「未登录」。
- 接口 `GET /api/acp/auth?mode=safe`。
- 前端 `sweepAuth()`：按队列串行，跳过刚问过的（10 分钟 TTL）与正在手动认证的。

### 涉及文件

- `internal/acp/auth.go`（`AuthStatusSafe` + `probeLoginState(..., safe)`）
- `internal/admin/acp.go`（`mode=safe`）
- `internal/acp/auth_test.go`（safe 不调 authenticate；能建会话即已登录）
- `web/src/components/settings/AcpSection.vue`（`sweepAuth` + 进度提示）
- `web/tests/acp-settings.test.js`
