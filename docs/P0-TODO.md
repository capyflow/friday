- [x] 聊天 `mode` 随请求体传递，不再拼进消息文字；计划模式产出结构化清单并在聊天内出计划卡。
- [x] 计划需用户确认才开始；支持暂停/继续/取消、单步重试或跳过，每步显示 token。
- [x] 一步一次提问、独立会话 `plan-<id>`、独立轨迹与成本归属；重启后在跑的计划降为暂停，不自动续跑。
- [x] 目标模式落成带预算的智能任务：隔离会话 `goal-<id>` 多轮推进，`[达成]/[受阻]/[继续]` 协议，
  步数与 token 上限、并发上限、步边界软停，成果经通知中心投递。
- [x] 计划确认不复用审批队列（后者在非 confirm 档自动放行，会造成"没人确认计划"的倒退）。
- [ ] 真实模型下验证规划 JSON 的稳定性与降级路径（解析失败退化为普通回答并在前端明示）。

验收：选「计划」提问 → 出步骤卡 → 确认 → 逐步 done 并显示每步 token；`kill -9` 重启后计划仍在且为暂停态，
可手动续跑。建一个目标 → 多轮跑到达成或预算耗尽 → 通知中心有成果、`/api/traces?session=goal-<id>` 可逐步展开、
同一目标二次启动被拒。取消目标后其会话与轨迹被释放。

## 本轮实现说明

- 新部署账号先创建，旧账号兼容；远程首次初始化通过启动凭据预置。
- 模型诊断发送少量测试文本/可选1x1图片，实际返回成功才显示可用；测试不会自动保存配置。
- 截止时间不会自动创建提醒，只有显式提醒时间才关联任务；同步失败明确反馈已保存状态并提供恢复同步入口。
- 通知已读、延后计划、任务编辑/暂停状态均持久化；桌面系统提示仅在显式启用及系统允许后发出，失败保留通知中心。
- 详细入口、API和验收方法见 [P0 使用与验收](P0-USAGE.md)。
