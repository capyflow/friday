# 内置 agent 的编码能力

> 2026-11-11 起。Friday 的定位一直是「跨 agent 宿主」：编码活外包给 codex / claude / opencode，
> 内置 agent 做兜底。但兜底不等于不能用——从这一轮起，内置 Friday 自己就是一套完整的编码面，
> 在没有任何外部 agent 的情况下也能独立把需求做完。

## 一条完整的工作流

内置 agent 在工作区会话里拿到一个「改掉 X」的活，现在能自己走完：

1. **定位**：`find_files` 看项目结构、`search_code` 搜内容（正则或字面量），落到具体文件与行号；
2. **读**：`read_file` 读那一段（可 `offset` 续读）；
3. **看现状**：`git_status` 看当前分支与未提交改动、`git_diff` 看已有差异——避免盖掉别人的改动；
4. **改**：`edit_files` 一次改多处/多个文件（old 须唯一匹配，整批要么全改要么不改），
   整份重写才用 `write_file`，单处替换用 `edit_file`；
5. **挪/删**：`move_file` 改名或移动（目标已存在默认拒绝，覆盖传 `overwrite=true`，旧目标备份成 `.bak`），
   `delete_file` 删文件（**不硬删**，移入回收站可恢复；目录要先用 `move_file` 移走）；
6. **验证**：`exec_command` 在**项目目录里**跑测试/构建，把真实结果（通过/失败/报错）说出来；
7. **复核**：`git_diff` 确认改了什么，需要给用户看时走工作区时间线的变更清单与一键还原。

活儿大的时候还有两条编排路径：

- **`delegate_task`**：派一个子任务到隔离子会话（独立上下文，可并行），指令要写自足（子任务看不到主对话），
  默认只读——适合「摸清某块代码」「同时查几处」这类互不相干的调查。子任务不能再派子任务（嵌套上限 1 层）。
- **`create_plan`**：把多步活儿拆成步骤清单并按步执行。每步一次独立提问、一条独立轨迹、一份独立成本，
  步骤之间可暂停/重试/跳过；计划记着发起时的工作目录，所以每一步都落在同一个项目里。
  执行期间在「自动化 → 计划」页看进度、随时暂停或取消。

## 工具契约

| 工具 | 作用 | 关键语义 |
|------|------|----------|
| `search_code` | 按内容搜 | `pattern` 是 Go 正则；`fixed=true` 按字面量。返回 `路径:行号: 内容`。跳过 `.git`/`node_modules`/`dist` 等依赖与构建目录、二进制、>2MB 文件。`glob` 按文件名过滤，`max_results` 上限 500。 |
| `find_files` | 按文件名找 | glob 模式：`**` 跨目录，`*`/`?` 单层通配。模式不含 `/` 时按文件名匹配（含子目录）。 |
| `git_status` | 看分支与未提交改动 | 只读；从会话工作目录往上找 `.git`。 |
| `git_diff` | 看差异 | `staged=true` 看已暂存部分，`path` 限定文件/目录。 |
| `git_log` | 看最近提交 | 默认 10 条，最多 50 条。 |
| `edit_files` | 批量精确编辑 | `edits` 数组，每项 `{path, old, new}`。old 在文件里必须恰好出现一次；先全量校验再落盘；中途失败回滚已写文件；confirm 模式下整批一张审批卡。 |
| `move_file` | 改名/移动 | `from` 必须存在，`to` 的父目录必须存在，两者都在允许根内。目标已存在默认拒绝（**任何写动作之前就拒绝**，源不会丢）；`overwrite=true` 时旧目标先备份成 `<to>.bak`。软链移动的是链接本身。跨卷自动退回复制+删除。 |
| `delete_file` | 删文件 | 只支持文件（目录要先 `move_file` 移走）。**不硬删**：移入回收站（系统临时目录下的 `friday-trash`，文件名带时间戳，原子防撞名），返回值给出完整路径与恢复方法。 |
| `delegate_task` | 派子任务 | `task` 要自足。子会话独立上下文、默认只读、跑完即清（不留痕在 session.json）。嵌套上限 1 层。 |
| `create_plan` | 列步骤并按步执行 | `goal` + `steps[{title, detail, doneWhen}]`。默认 `auto_start=true` 立刻执行（`false` 则等你确认）。每步仍在计划自己的会话里跑，目录记在计划上。 |
| `exec_command` | 跑命令 | 工作目录 = 本次会话的工作目录；`cwd` 可另指定；`timeout` 上限 10 分钟。长输出保留头尾并标注省略量（失败信息在末尾不会被截掉）。 |

只读工具（检索、git、read/list）不进审批队列；写类工具（`write_file`/`edit_file`/`edit_files`/
`move_file`/`delete_file`）沿用既有语义：confirm 模式下走审批队列，写前自动备份 `.bak`。

## 行为约束：编码守则

带项目目录的会话（工作区会话、工作模式）在会话开始时自动注入一段守则（`internal/agent/project.go`
的 `codingRules`）：先搜再改、改前先读、改动要小而准、动手前先看 git 现状、改完要验证并如实报结果、
活儿大就拆开并行。

这一段是刻意分层的：它只对「绑定了项目目录」的会话注入，生活模式的日常对话不会平白多出这几百字；
而它恰好是内置 agent 从「管家」变成「能自己把活干完」时最缺的东西——工具齐了，纪律不补，
模型仍然会凭猜测改文件、改完不验证。

## 还缺什么（诚实清单）

按对「独立完成需求」的影响排序：

| 缺口 | 影响 | 建议 |
|------|------|------|
| 真正的补丁语义（apply_patch） | `edit_files` 依赖 old 唯一匹配，改大段结构仍笨拙 | 后续做 unified diff 入口 |
| 子任务只能只读 | 派出去的子任务不能改文件（并行改同一项目会互相覆盖） | 需要时按任务显式授权 |
| 计划步骤不跨会话 | 每步一条独立上下文，后一步看不到前一步的完整过程（只看得到结论摘要） | 与既有设计一致，暂不动 |
| 技能不能带脚本、没有 tool hooks | 不能「改完自动格式化 / 自动跑 lint」 | P2-13 |
| 没有沙箱 | exec 以宿主用户身份跑，安全只靠字符串级黑白名单 | 高危场景用 seatbelt / 容器 |
| 没有 LSP / 符号索引 | 只能文本搜索，找不到「谁调用了这个函数」 | 依赖图可选 |
| 模型与权限全局共享 | 两条工作区会话不能各选模型 | 内置会话放开按会话选模型 |
| 工作区里没有计划面板 | 计划在「自动化 → 计划」页看，工作区时间线里只有轨迹 | 前端补一块（另一条工作流在动 web/，避免冲突） |

## 怎么验证

```bash
go test ./internal/tools/... ./internal/agent/... ./internal/plan/...
```

覆盖点：检索的 glob/字面量/二进制跳过、git 三件套与非仓库报错、批量编辑的
「多处匹配整批拒绝且不改任何文件」「中途失败回滚」、文件生命周期（目标已存在先拒绝再动手、
覆盖留 .bak、软链移动的是链接本身、回收站防撞名）、命令工作目录（会话目录 / 显式 cwd /
回落临时目录）与长输出保尾、子任务（嵌套上限、上下文隔离、跑完清理）、
计划（步骤/状态/目录、auto_start、步骤确实落在计划自己的目录里）、编码守则只对带目录会话注入。
